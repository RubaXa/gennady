# Module: plugins/anystack

## 1. Module Vision

`StackPlugin`-заглушка для репозиториев, у которых плагина нет: собственных гейтов не приносит, а весь список гейтов автор пишет в `stack.anystack.extraGates`. Термины (Gate, Scope, Capability, ENV_FAIL, VIOLATION, Run replica) — [stack.spec.md §2](../../../specs/stack/stack.spec.md).

**Parent scope:** [`stack`](../../../specs/stack/stack.spec.md) · **Локальность:** [`plugins`](../../../specs/plugins/plugins.spec.md) · **E2E-механизм:** [`stack/e2e`](../../../specs/stack/e2e/e2e.spec.md)

Зачем это нужно: экзотический стек (или монорепа с самодельным `make`-пайплайном) сегодня упирается в `NO_STACK_DETECTED` — `verify` отказывается работать, пока кто-нибудь не напишет плагин. Но всё, что репозиторию реально нужно от gennady, — это **исполнитель гейтов**: реплика прогона, вердикты, `envFail`-правила, таймауты, отчёт, JSON для оркестратора. Заглушка отдаёт это всё, не изобретая детекции. Цена: `id` плагина остаётся обязательным — это пространство имён гейтов (`anystack:build`) и ключ конфиг-секции.

Золотой пример:

```yaml
stack:
  use: [anystack]
  anystack:
    extraGates:
      - id: build
        argv: [make, build]
      - id: test
        argv: [make, test]
        timeout: 20m
```

## 2. Capability Support

| Capability     | Поддержка       | Комментарий                                                               |
| -------------- | --------------- | ------------------------------------------------------------------------- |
| `detect`       | ✅ всегда       | Возвращает detection для любого корня — но только когда выбран (§3)       |
| `verify`       | ✅ обязательный | `planGates` возвращает пустой список; гейты добавляет конфиг              |
| `fix`          | ➖ не объявляет | Фиксер задаётся полем `fixer` у своего гейта (stack.spec §4.4)            |
| `gateIds`      | ✅ пустой       | Словарь гейтов пуст: `extraGates` не проверяются по нему (config.spec §3) |
| `sandboxLinks` | ➖ не объявляет | Что является средой, а что деревом, знает только автор конкретного гейта  |

## 3. Detection

**Плагин никогда не участвует в автодетекции.** Поле `optIn: true` исключает его из кандидатов, пока `stack.use` не назовёт его явно. Иначе плагин, совпадающий с любым репозиторием, совпадал бы **всегда** — и `NO_STACK_DETECTED` перестал бы существовать как класс ошибки: репозиторий без стека молча «проверялся» бы нулём гейтов. Такое поведение хуже отказа.

Следствия, которые нужно держать:

- `verify` в репозитории без конфига по-прежнему завершается кодом 5, а `anystack` виден в ростере известных стеков вместе с подсказкой про `stack.use` — то есть заглушка обнаруживается ровно там, где в неё упираются;
- будучи выбранным, `detect` не читает диск и не запускает процессов: возвращать нечего, кроме факта выбора;
- `summary` в `--plan` говорит, откуда придут гейты, потому что «стек не определялся» — это единственное, что стоит знать про эту детекцию.

## 4. Scope Resolution

`resolveScope` возвращает запрошенный режим как есть с примечанием, что скоуп ничего не сужает. Причина: гейт из конфига — это фиксированный `argv`, и что он прочитает, решает только его собственная команда. Флаги `--all`/`--only`/позиционные цели продолжают работать как фильтры **гейтов** (это уровень `verify`), но не превращаются в аргументы команды.

## 5. Gates

Собственных гейтов нет — `planGates` возвращает `[]`. Всё остальное приходит из `applyStackConfig` (stack.spec §4.5) и получает полный паритет с built-in-гейтами (FR-STACK-15): `timeout`, `env`, `cwd`, `requires`, `fixer`, `envFail`, `outputMeansFailure`, `driftMeansFailure`.

**Выбран, но гейтов нет.** Прогон завершается `ZERO_GATES` и кодом 1: прогон, который ничего не исполнил, не является успехом. Синтетического «гейта-заглушки» здесь нет намеренно — гейт означает проверку, а отсутствие конфигурации проверкой не является.

## 6. Use Cases to Test (E2E-матрица)

| #   | Случай                                    | Ожидание                                                |
| --- | ----------------------------------------- | ------------------------------------------------------- |
| 1   | Только `extraGates`, стек не определяется | гейты исполняются, `exit 0` (`any-extra-gates-only`)    |
| 2   | Конфига нет вовсе                         | `NO_STACK_DETECTED`, `exit 5` (`any-not-auto-detected`) |
| 3   | Выбран, `extraGates` пуст                 | `ZERO_GATES`, `exit 1` (`any-no-gates-configured`)      |
| 4   | `envFail`-правило на гейте из конфига     | `env-fail` + `hint` (`any-env-fail-rule`)               |

## 8. Handoff to Task Scaffolding

**Structural changes:** `StackId` пополняется `'anystack'`; `StackPlugin` получает необязательное `optIn`; `detectStacks` фильтрует opt-in-плагины; `plugins/index.ts` регистрирует плагин.

**Open risks:**

- **Сообщение `ZERO_GATES` неспецифично.** Для автора, который только что выбрал `anystack` и ещё не написал гейты, строка «nothing was executed» не подсказывает следующий шаг; `--plan` подсказывает. Специфичный текст потребовал бы либо синтетического гейта (§5 — отклонено), либо доступа `detect` к конфигу.
