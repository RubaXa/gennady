# Module: plugins/node

## 1. Module Vision

`StackPlugin` для npm-репозиториев: детекция по `package.json` в корне, гейты — **классифицированные npm-скрипты** самого репозитория. Плагин не приносит собственный тулчейн: он распознаёт, какой из уже объявленных скриптов является typecheck'ом, линтером, тестами, форматтером, и запускает их через `npm run`. Термины — [stack.spec.md §2](../../../specs/stack/stack.spec.md).

**Parent scope:** [`stack`](../../../specs/stack/stack.spec.md) · **E2E-механизм:** [`stack/e2e`](../../../specs/stack/e2e/e2e.spec.md) · **Доктрина E2E:** [`infra-e2e`](../../../specs/infra-e2e/infra-e2e.spec.md)

Ключевое отличие от [golang](../../golang/specs/golang.spec.md): там гейты — **known-good команды тулчейна**, здесь — **чужие скрипты неизвестного качества**. Отсюда две особенности, определяющие всю спеку: скрипты приходится классифицировать эвристикой по имени и телу, и их приходится **экранировать на мутацию** — `lint` в половине репозиториев означает `prettier --write`.

## 3. Detection

Маркер — `<root>/package.json`. **Битый манифест не отменяет детекцию**: плагин остаётся активным и отдаёт диагностику — иначе поломка становится тихой («стек не распознан» вместо «у вас невалидный JSON»).

| Диагностика             | Когда                                                      |
| ----------------------- | ---------------------------------------------------------- |
| `NODE_INVALID_MANIFEST` | `package.json` существует, но не парсится как JSON         |
| `NODE_NO_SCRIPTS`       | скриптов, классифицируемых как верификационные, не нашлось |

## 4. Scope Resolution

npm-скрипты — **репо-уровневые команды**: они не принимают список файлов и не умеют сужаться. Поэтому позиционные цели скоуп не сужают (D-STACK-006), а `note` честно сообщает состав: `npm scripts (<имена>), repo-wide`. Это осознанная асимметрия с golang: обещать сужение, которого нет, хуже, чем его отсутствие.

## 5. Gates

Гейт = один npm-скрипт, выбранный на класс. Классы и порядок: `typecheck → gennady → lint → test → format`. Таймаут у всех — 10m (D-STACK-007).

| Класс       | Что распознаётся                                                   | Приоритет выбора                         |
| ----------- | ------------------------------------------------------------------ | ---------------------------------------- |
| `typecheck` | имена `type-check`/`typecheck`/`tsc`/`lint:ts` либо `tsc --noEmit` | `type-check` 10, `typecheck` 10, `tsc` 5 |
| `gennady`   | тело содержит `gennady`, либо имя `lint:contracts`                 | `lint:contracts` 10                      |
| `lint`      | eslint/biome/oxlint в теле                                         | по имени скрипта                         |
| `test`      | тест-раннеры в теле                                                | по имени скрипта                         |
| `format`    | имя `format`/`format:check` либо prettier/biome в теле             | `format:check` 10, `format` 5            |

**Экранирование мутации (D-STACK-005).** Скрипт, чьё тело содержит `--fix`, `--autofix` или `--write`, планируется как **видимый skip** с причиной, а не исполняется: гейт наблюдает. Автор конфига может дать check-only форму через `overrideGates.<class>.argv` — тогда skip снимается. Собственный `gennady.yaml` проекта — живой пример: `lint` скипнут (это `prettier --write`), а `gennady` переопределён на check-only argv.

Асимметрия с golang в приоритете `format:check` над `format` — того же происхождения: `format` обычно мутирует, `format:check` — нет.

## 6. Use Cases to Test (E2E-матрица)

Механизм — [`stack/e2e`](../../../specs/stack/e2e/e2e.spec.md). Фикстуры не ходят в реестр: зависимости либо отсутствуют, либо вендорятся в шаблон (infra-e2e §3.5).

| Фикстура                   | Гейт / прогон    | Состояние фикстуры                                | Ожидание                                                 | Флаги            |
| -------------------------- | ---------------- | ------------------------------------------------- | -------------------------------------------------------- | ---------------- |
| `node-clean-full`          | **весь план**    | скрипты проходят                                  | `pass`, exit 0                                           | без флагов       |
| `node-test-fail`           | `node:test`      | падающий тест-скрипт                              | `fail`                                                   | `--only`         |
| `node-typecheck-fail`      | `node:typecheck` | `tsc --noEmit` с ошибкой типов                    | `fail`                                                   | `--only`         |
| `node-mutating-lint`       | `node:lint`      | `lint` = `prettier --write`                       | `skipped`, причина называет мутацию                      | `--plan`         |
| `node-mutating-overridden` | `node:lint`      | то же + `overrideGates.lint.argv` (check-only)    | исполняется, skip снят                                   | `--plan --json`  |
| `node-invalid-manifest`    | —                | битый `package.json`                              | стек **детектится**, `NODE_INVALID_MANIFEST`, гейтов нет | `--plan`         |
| `node-no-scripts`          | —                | валидный манифест без верификационных скриптов    | `NODE_NO_SCRIPTS`, `ZERO_GATES`, exit 1                  | без флагов       |
| `node-sandbox-links`       | `node:test`      | тест требует пакет из `node_modules`              | `pass` — `node_modules` симлинкован в реплику            | без флагов       |
| `node-missing-modules`     | `node:test`      | `node_modules` отсутствует                        | `fail` (не `violation`): скрипт не пишет в дерево        | без флагов       |
| `node-script-mutates`      | extra            | npm-скрипт пишет файл в дерево                    | `violation` + список файлов                              | без флагов       |
| `node-repo-wide`           | `node:test`      | позиционная цель передана                         | скоуп репо-уровневый, `note` это сообщает                | позиционная цель |
| `node-plus-golang`         | **весь план**    | `package.json` **и** `go.mod` в одном репозитории | активны оба стека, гейты обоих в одном отчёте            | без флагов       |

Фикстура `node-plus-golang` покрывает свойство scope-спеки, которое не проверить внутри одного плагина: репозиторий может принадлежать нескольким стекам одновременно, и `--only`/`--skip` по короткому имени применяются ко всем активным.

## 7. Inter-Module Dependencies

- **Depends on:** [`stack`](../../../specs/stack/stack.spec.md) (типы, раннер, реестр), `classify-npm-scripts` (внутренняя эвристика модуля)
- **Sibling:** [`plugins/golang`](../../golang/specs/golang.spec.md) — независимая зона ответственности
- **Verified by:** [`stack/e2e`](../../../specs/stack/e2e/e2e.spec.md) по матрице §6
- **External:** `npm` (обязателен), `npx`

## 8. Handoff to Task Scaffolding

- **Implementation files (существуют):** `node-plugin.ts`, `classify-npm-scripts.ts`
- **Fixture files to be created:** `plugins/node/e2e/fixtures/node-*` по §6 (12 фикстур)
- **Open risks:**
  - **эвристика классификации** — главный источник ложных срабатываний: незнакомый раннер не распознаётся (гейт молча отсутствует), а нестандартное имя может попасть в чужой класс. Смягчение: `--plan` печатает выбор `класс→скрипт`, диагностика `NODE_NO_SCRIPTS` при пустом наборе, `extraGates` как обходной путь
  - **вендоринг зависимости в фикстуру** для `node-sandbox-links` — требуется крошечный пакет в шаблоне, без обращения к реестру
  - `node-missing-modules` зависит от текста ошибки npm — фикстура утверждает только вердикт
