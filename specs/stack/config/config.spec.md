# Module: `config` (stack configuration)

**Module:** config · **Parent scope:** [stack](../stack.spec.md) · **Tasks:** TSK-95

<!--SECTION:MODULE_VISION-->

## 1. Module Vision

Единственная точка, где репозиторий декларирует отклонения своей инфраструктуры от встроенных плагинов. Цель: **разные репозитории отличаются конфигом, а не командами**. Термины (Gate, Stack, Capability, …) — [stack.spec.md §2](../stack.spec.md).

**Формат и файлы:**

| Файл           | Формат   | Git            | Назначение                                                                                                                                                        |
| -------------- | -------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gennady.yaml` | YAML 1.2 | **коммитится** | Проектный конфиг — источник истины для репозитория                                                                                                                |
| `.gennadyrc`   | JSON     | gitignored     | Личный конфиг разработчика: секция `models` может содержать API-ключи (поэтому файл исторически в gitignore); секция `stack` — личный override проектного конфига |

**Почему два файла.** «rc» — юниксовая конвенция _run commands_: личный дот-файл пользователя. `.gennadyrc` уже существует, уже в gitignore и уже носит секреты (`models[].key`) — коммитить его нельзя, un-ignore опасен (утечка ключей). Репо-шаримая конфигурация поэтому живёт в отдельном, видимом, коммитимом файле.

**Почему YAML для проектного файла.** Инфраструктурный конфиг без комментариев не живёт: каждое отклонение («skip lint, пока golangci-lint не пересобран под go1.26») обязано нести причину рядом с собой. YAML даёт комментарии и человекочитаемость; цена — YAML-парсер как dev-зависимость, бандлится Vite (политика zero-runtime-deps соблюдена). `.gennadyrc` остаётся JSON — он уже существует в этом формате и парсится текущим `GennadyRc`.

**Precedence (discovery order), первый файл с секцией `stack` побеждает целиком — глубокого мерджа между файлами нет:**

1. `.gennadyrc` в корне репозитория (личный override)
2. `gennady.yaml` в корне репозитория (проектный)
3. `.gennadyrc` в `$HOME` (личный глобальный)

_Rationale отсутствия мерджа: спор «какое поле из какого файла» — источник невоспроизводимых прогонов; выигравший файл виден в `verify --plan`._

## 2. Module Usage Example

`gennady.yaml` Go-репозитория внутри корпоративного периметра:

```yaml
stack:
  # Ограничить авто-детекцию (репо содержит и package.json для тулинга,
  # но верифицируем только Go):
  use: [golang]

  golang:
    # golangci-lint в образе собран go1.25, модуль требует go1.26 —
    # линтер паникует; вернуть после обновления образа (TICKET-123).
    skipGates: [lint]

    testTimeout: 10m

    overrideGates:
      build:
        env:
          GOPROXY: http://gomods.mail.cloud.devmail.ru:3000/ # корп-прокси модулей
      test:
        argv: [make, test] # тесты гоняются только через make (CGO-флаги)
        timeout: 15m

    extraGates:
      - id: codegen-drift
        argv: [make, check-generated]
        timeout: 3m
      - id: easyjson-drift
        argv: [scripts/check-easyjson.sh]
        cwd: src/mail
        timeout: 2m
        outputMeansFailure: true # скрипт печатает разъехавшиеся файлы, exit 0
```

Личный `.gennadyrc` (JSON), временно выключающий тесты на слабой машине:

```json
{ "stack": { "golang": { "skipGates": ["lint", "test"] } } }
```

## 3. Config Reference (все поля)

### 3.1 `stack` (корень секции)

| Поле               | Тип        | Default           | Описание                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ---------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `stack.use`        | `string[]` | _(авто-детекция)_ | Ограничить реестр плагинов перечисленными id. Встроенные id: `node`, `golang`. Неизвестный id → диагностика `STACK_USE_UNKNOWN` (v1). v2 (FR-STACK-11): ссылка на внешний плагин, например `gitlab.corp.mail.ru/sdd/my-awesome-stack`. `use` **ограничивает кандидатов** — детекция всё равно решает (см. stack.spec §3) |
| `stack.<pluginId>` | `object`   | `{}`              | Per-plugin секция; ключ — id плагина. Поля ниже                                                                                                                                                                                                                                                                          |

### 3.2 `stack.<pluginId>` (общие поля любого плагина)

| Поле            | Тип                               | Default | Описание                                                                                                                                                                                           |
| --------------- | --------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skipGates`     | `string[]`                        | `[]`    | Id гейтов, исключаемых из плана. Скип **виден** в `--plan`; молчаливого исключения нет                                                                                                             |
| `overrideGates` | `map<gateId, GateSpec>`           | `{}`    | Переопределение встроенного гейта по id. Не заданные поля наследуются от исходного гейта. `argv`-override снимает планировочный skip (автор конфига утверждает, что команда исполнима в этом репо) |
| `extraGates`    | `GateSpec[]` (+обязательный `id`) | `[]`    | Репо-специфичные гейты, добавляются **после** встроенных, в порядке объявления. Контракт «гейт не мутирует дерево» распространяется и на них (D-STACK-005)                                         |

**Порядок применения (FR-STACK-05):** план плагина → `overrideGates` → `skipGates` → `extraGates`.

### 3.3 `GateSpec` — общая схема для `overrideGates` и `extraGates`

_Одна схема на оба места употребления — намеренно (ревью: «must have similar config schema»)._

| Поле                 | Тип                                | Default (override) | Default (extra) | Описание                                                                                                                |
| -------------------- | ---------------------------------- | ------------------ | --------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `id`                 | `string`                           | — (ключ map)       | **обязателен**  | Id гейта, уникален внутри плагина. В отчётах гейт именуется `<stack>:<id>`                                              |
| `argv`               | `string[]`                         | наследуется        | **обязателен**  | Команда и аргументы; исполняется spawn'ом **без shell** — никакой интерполяции, пайпов, `&&`                            |
| `cwd`                | `string` (relative to repo root)   | наследуется        | корень репо     | Рабочая директория гейта                                                                                                |
| `env`                | `map<string,string>`               | наследуется        | `{}`            | Переменные окружения, мержатся **поверх** окружения процесса. Пример: `GOPROXY` на корп-прокси без переписывания `argv` |
| `timeout`            | duration (`"90s"`, `"5m"`, `"1h"`) | наследуется        | `"10m"`         | Per-gate таймаут; превышение → статус `TIMEOUT`. Глобального таймаута нет (D-STACK-007)                                 |
| `outputMeansFailure` | `boolean`                          | наследуется        | `false`         | Контракт «exit 0 + непустой stdout = FAIL» (семейство `gofmt -l`)                                                       |

### 3.4 `stack.golang` (плагин-специфичные ключи)

| Поле          | Тип             | Default        | Описание                                                                                                                                                                        |
| ------------- | --------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `testTimeout` | duration        | `10m`          | Значение `go test -timeout=<v>`; одновременно дефолт `timeout` гейта `test`                                                                                                     |
| `lintConfig`  | `string` (path) | _(авто-поиск)_ | Путь к конфигу golangci-lint; передаётся через `-c`. Авто-поиск: `.golangci.{yml,yaml,toml,json}`, затем `golangci.{yml,yaml}` (без точки — golangci-lint сам такие не находит) |
| `tidy`        | `boolean`       | `false`        | Включить гейт `tidy` (`go mod tidy -diff`) в план по умолчанию (эквивалент постоянного `--tidy`)                                                                                |

**Дефолтные таймауты встроенных гейтов golang:** `build`/`vet`/`lint`/`tidy` — `5m`, `fmt` — `1m`, `test` — `testTimeout`.

### 3.5 `stack.node` (плагин-специфичные ключи)

v1 — нет плагин-специфичных ключей; конфигурация через общие `skipGates`/`overrideGates`/`extraGates`. **Дефолтный таймаут** всех npm-гейтов — `10m`.

### 3.6 CLI-переопределения (одноразовые, поверх конфига)

| Флаг           | Эквивалент в конфиге               | Семантика                                     |
| -------------- | ---------------------------------- | --------------------------------------------- |
| `--stack=<id>` | `stack.use: [<id>]`                | На один прогон                                |
| `--skip=<a,b>` | `skipGates` (все активные плагины) | Поверх конфига; неизвестный id гейта → exit 4 |
| `--only=<a,b>` | —                                  | Оставить только перечисленные гейты           |
| `--tidy`       | `stack.golang.tidy: true`          | На один прогон                                |

## 4. Module Contracts (DbC)

### 4.1 Loading & Degradation

- **Runtime Backing:** `real-runtime` · **Verification Levels:** `unit`

- Preconditions: файлы по §1 могут отсутствовать — это валидное состояние (чистая авто-детекция, встроенные гейты).
- Postconditions:
  - Discovery строго по §1; выигравший файл и его путь видны в `verify --plan`.
  - Битый YAML/JSON, не-объект в `stack`, неверный тип поля → диагностика `STACK_CONFIG_INVALID` с путём и полем; прогон продолжается **без** конфига. Конфиг никогда не роняет verify.
  - Неизвестный id в `use` → `STACK_USE_UNKNOWN` с перечнем известных id.
  - Неизвестное поле в известной секции → диагностика `STACK_CONFIG_UNKNOWN_FIELD` (опечатки не игнорируются молча).
- Invariants: загрузка конфига не мутирует дерево и не исполняет команд.

### 4.2 Application

- Postconditions:
  - Порядок: `overrideGates` → `skipGates` → `extraGates`; порядок встроенных гейтов сохраняется; extra — в порядке объявления после встроенных.
  - Override без поля наследует значение исходного гейта; `extraGates` без `timeout` получает `10m`; без `outputMeansFailure` — `false`.
  - `env` мержится поверх `process.env` (переменная из конфига побеждает).
  - Duration-строки: `<число><s|m|h>`; невалидная строка → `STACK_CONFIG_INVALID` этого поля, гейт получает дефолт.
- Invariants: применение конфига — чистая функция плана; сам конфиг не порождает исполнения.

## 5. Module Decision Log

### D-CFG-001 — YAML для проектного файла, JSON для личного

- **Status:** active (по ревью)
- **Why:** комментарии в инфраструктурном конфиге обязательны (§1); `.gennadyrc` уже существует как JSON и уже gitignored из-за секретов. Парсер YAML — dev-dep, бандлится Vite.
- **Rejected alternatives:** JSON для проектного файла (нет комментариев); un-ignore `.gennadyrc` (риск утечки ключей); TOML (ещё одна экосистема без выигрыша над YAML).

### D-CFG-002 — Winner-takes-all вместо глубокого мерджа файлов

- **Status:** active
- **Why:** мердж трёх источников по полям делает прогон невоспроизводимым и недебажимым («откуда взялся этот таймаут?»). Один выигравший файл, его имя — в `--plan`.
- **Risk accepted:** личный override обязан повторить нужные проектные поля. Осознанно: личный файл — временный инструмент разработчика.

### D-CFG-003 — Duration-строки, а не миллисекунды

- **Status:** active
- **Why:** `"10m"` читается и ревьюится; `600000` — нет. Go-подобный формат знаком целевой аудитории (backend).
