# Module: `config` (stack configuration)

**Module:** config · **Parent scope:** [stack](../stack.spec.md) · **Tasks:** TSK-95

<!--SECTION:MODULE_VISION-->

## 1. Module Vision

Единственная точка, где репозиторий декларирует отклонения своей инфраструктуры от встроенных плагинов. Цель: **разные репозитории отличаются конфигом, а не командами**. Термины (Gate, Stack, Capability, …) — [stack.spec.md §2](../stack.spec.md).

### 1.1 Файлы

| Файл                  | Формат   | Git            | Назначение                                                                                                                                                                                                                               |
| --------------------- | -------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<repo>/gennady.yaml` | YAML 1.2 | **коммитится** | Проектный конфиг — источник истины для репозитория                                                                                                                                                                                       |
| `<repo>/.gennadyrc`   | JSON     | gitignored     | Личный конфиг разработчика в репозитории: временные надстройки поверх проектного (тесты выключить на слабой машине, токен-авторизация внешней системы). Секция `models` может содержать API-ключи — поэтому файл исторически в gitignore |
| `$HOME/.gennadyrc`    | JSON     | вне git        | Личный глобальный конфиг разработчика: машинно-специфичные значения по умолчанию для всех репозиториев (например, корп-прокси). Тот же формат и схема, что у репозиторного `.gennadyrc`                                                  |

**Почему два вида файлов.** «rc» — юниксовая конвенция _run commands_: личный дот-файл пользователя. `.gennadyrc` уже существует, уже в gitignore и уже носит секреты (`models[].key`) — коммитить его нельзя, un-ignore опасен (утечка ключей). Репо-шаримая конфигурация поэтому живёт в отдельном, видимом, коммитимом файле.

**Почему YAML для проектного файла.** Инфраструктурный конфиг без комментариев не живёт: каждое отклонение («skip lint, пока golangci-lint не пересобран под go1.26») обязано нести причину рядом с собой. YAML даёт комментарии и человекочитаемость; цена — YAML-парсер как dev-зависимость, бандлится Vite (политика zero-runtime-deps соблюдена). `.gennadyrc` остаётся JSON — он уже существует в этом формате и парсится текущим `GennadyRc`.

### 1.2 Merge: deep-merge с per-key провенансом

Секция `stack` собирается **deep-merge'ем** всех трёх источников. Приоритет по убыванию:

1. `<repo>/.gennadyrc` — личный репозиторный
2. `<repo>/gennady.yaml` — проектный
3. `$HOME/.gennadyrc` — личный глобальный

Правила merge:

- **Объекты** сливаются рекурсивно по ключам.
- **Скаляры и массивы** — значение из более приоритетного источника **замещает** целиком (массивы не конкатенируются: это позволяет личным конфигом и добавить — повторив список с добавкой, — и убрать: `skipGates: []` возвращает всё, что проект выключил).
- **Per-key провенанс**: для каждого эффективного ключа запоминается файл-победитель; `verify --plan` показывает провенанс у каждого значения, отличного от дефолта (см. Golden DX в stack.spec §6).

Личный сценарий из ревью работает без ручной трансляции секций: чтобы добавить один персональный override, достаточно одного ключа в `.gennadyrc` — остальное придёт из `gennady.yaml`:

```json
{ "stack": { "golang": { "overrideGates": { "test": { "env": { "MY_TOKEN": "…" } } } } } }
```

_Историческая справка (вопрос из ревью): исходный `GennadyRc` (секция `models`) merge не делал — использовался первый прочитанный файл (cwd → HOME), т.е. winner-takes-all per-file. Для секции `stack` semantics осознанно другие; `models` не трогаем._

### 1.3 Совместимость схемы

Схема **не версионируется** отдельным ключом: конфиг всегда валидируется против схемы установленной версии «Геннадия». Строгая валидация (§4.1) делает любую несовместимость явной и actionable — неизвестный ключ или неверный тип печатается списком с подсказками, exit 4. Ломающие изменения схемы приезжают с релизами «Геннадия» и чинятся правкой конфига вместе с обновлением инструмента.

## 2. Module Usage Example

`gennady.yaml` Go-репозитория внутри корпоративного периметра:

```yaml
stack:
  # Ограничить авто-детекцию (репо содержит и package.json для тулинга,
  # но верифицируем только Go):
  use: [golang]

  golang:
    # golangci-lint в образе собран go1.25, модуль требует go1.26 —
    # линтер паникует; вернуть после обновления образа (TICKET-123).
    skipGates: [lint]

    overrideGates:
      build:
        env:
          GOPROXY: https://goproxy.example.com/ # корп-прокси модулей
      test:
        argv: [make, test] # тесты гоняются только через make (CGO-флаги)
        timeout: 15m

    extraGates:
      - id: tidy-drift
        argv: [go, mod, tidy, -diff] # дрейф go.mod; не-мутирующая форма
        timeout: 5m
      - id: easyjson-drift
        argv: [scripts/check-easyjson.sh]
        cwd: src/mail
        timeout: 2m
        outputMeansFailure: true # скрипт печатает разъехавшиеся файлы, exit 0
```

Личный `<repo>/.gennadyrc` (JSON): один персональный ключ поверх проектного конфига — deep-merge доносит остальное из `gennady.yaml`:

```json
{ "stack": { "golang": { "skipGates": ["lint", "test"] } } }
```

## 3. Config Reference (все поля)

### 3.1 Top-level

| Поле    | Тип      | Default | Описание                                                                                    |
| ------- | -------- | ------- | ------------------------------------------------------------------------------------------- |
| `stack` | `object` | `{}`    | Секция плагинной системы; поля ниже. Остальные top-level секции (`models`) — вне этой спеки |

### 3.2 `stack`

| Поле               | Тип        | Default           | Описание                                                                                                                                                                                                                                                 |
| ------------------ | ---------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stack.use`        | `string[]` | _(авто-детекция)_ | Ограничить реестр плагинов перечисленными id. Известные id: `node`, `golang`. Неизвестный id → ошибка конфига (§4.1). `use` **ограничивает кандидатов** — детекция всё равно решает (stack.spec §3). Внешние плагины — отложено (stack.spec D-STACK-001) |
| `stack.<pluginId>` | `object`   | `{}`              | Per-plugin секция; ключ — id плагина. Поля ниже. Ключ, не являющийся известным plugin id, → ошибка конфига                                                                                                                                               |

### 3.3 `stack.<pluginId>` (общие поля любого плагина)

_Плагин-специфичных ключей в v1 нет (stack.spec D-STACK-009); появятся — лягут в выделенный объект `stack.<pluginId>.config` со своей спекой._

| Поле            | Тип                               | Default | Описание                                                                                                                                                                                                                                                                              |
| --------------- | --------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skipGates`     | `string[]`                        | `[]`    | Id гейтов, исключаемых из плана. Скип **виден** в `--plan` с указанием файла-источника; молчаливого исключения нет                                                                                                                                                                    |
| `overrideGates` | `map<gateId, GateSpec>`           | `{}`    | Переопределение встроенного гейта по id. Не заданные поля наследуются от исходного гейта. `argv`-override снимает планировочный skip (автор конфига утверждает, что команда исполнима в этом репо). Ключ, не совпадающий ни с одним встроенным гейтом плагина, → ошибка конфига       |
| `extraGates`    | `GateSpec[]` (+обязательный `id`) | `[]`    | Репо-специфичные гейты, добавляются **после** встроенных, в порядке объявления. Контракт «гейт не мутирует дерево» принудителен (stack.spec D-STACK-005/013): мутация без `sandbox: true` → статус VIOLATION; мутирующим проверкам — `sandbox: true`, мутирующим операциям — `fixers` |
| `fixers`        | `FixerSpec[]`                     | `[]`    | Мутирующие операции для `gennady fix` (stack.spec §4.4). Схема повторяет `GateSpec`; исполняются в **реальном** дереве, после встроенных fixer'ов плагина, последовательно и fail-fast                                                                                                |

**Порядок применения (stack.spec FR-STACK-05):** план плагина → `overrideGates` → `skipGates` → `extraGates`.

### 3.4 `GateSpec` — общая схема для `overrideGates` и `extraGates`

_Одна схема на оба места употребления — намеренно (ревью round 1: «must have similar config schema»)._

| Поле                 | Тип                                | Default (override) | Default (extra) | Описание                                                                                                                                                                                                                                                                                              |
| -------------------- | ---------------------------------- | ------------------ | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                 | `string`                           | — (ключ map)       | **обязателен**  | Id гейта, уникален внутри плагина. Квалифицированное имя в отчётах и CLI: `<stack>:<id>`                                                                                                                                                                                                              |
| `argv`               | `string[]`                         | наследуется        | **обязателен**  | Команда и аргументы; исполняется spawn'ом **без shell** — никакой интерполяции, пайпов, `&&`                                                                                                                                                                                                          |
| `cwd`                | `string` (relative to repo root)   | наследуется        | корень репо     | Рабочая директория гейта                                                                                                                                                                                                                                                                              |
| `env`                | `map<string,string>`               | наследуется        | `{}`            | Переменные окружения, мержатся **поверх** окружения процесса. Пример: `GOPROXY` на корп-прокси без переписывания `argv`                                                                                                                                                                               |
| `timeout`            | duration (`"90s"`, `"5m"`, `"1h"`) | наследуется        | `"10m"`         | Per-gate таймаут; превышение → статус `TIMEOUT`. Глобального таймаута нет (stack.spec D-STACK-007). Гейт с собственным флагом таймаута у инструмента (golang `test`) рендерит это же значение во флаг (`go test -timeout=<v>`)                                                                        |
| `outputMeansFailure` | `boolean`                          | наследуется        | `false`         | Контракт «exit 0 + непустой stdout = FAIL» (семейство `gofmt -l`)                                                                                                                                                                                                                                     |
| `sandbox`            | `boolean`                          | наследуется        | `false`         | Drift-гейт (stack.spec §2): мутация ожидаема, непустой drift реплики — вердикт FAIL. Для мутирующих проверок (канонический `make generate`); вместе с `skipGates` + `--only` даёт паттерн «быстрый скоуп-дефолт, полный прогон адресно». В `fixers` — ошибка конфига (fixer всегда в реальном дереве) |

**Дефолтные таймауты встроенных гейтов:** golang — `build`/`vet`/`lint` `5m`, `fmt` `1m`, `test` `10m`; node — все npm-гейты `10m`.

### 3.5 CLI (одноразовые надстройки поверх конфига)

Стек-специфичных CLI-флагов нет. Гейты в `--only`/`--skip` адресуются **квалифицированно `stack:gate`** (нотация совпадает с именами в отчётах: `golang:build`) или коротко `gate` — короткое имя применяется во всех активных стеках. Неизвестное имя → exit 4.

| Флаг                  | Семантика                                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--stack=<id>[,<id>]` | Одноразовый эквивалент `stack.use`                                                                                                                                                                                              |
| `--skip=<a,b>`        | Дополнительные skip'ы поверх `skipGates`; `golang:lint` или `lint`                                                                                                                                                              |
| `--only=<a,b>`        | Оставить только перечисленные гейты; `golang:build,golang:vet` или `build,vet`. Явно названный гейт **освобождается** от конфигового `skipGates` — паттерн «дорогой E2E-гейт: skip по умолчанию, адресный запуск перед мерджем» |
| `--full-output`       | Не усекать вывод гейтов в `--json`-результатах                                                                                                                                                                                  |

## 4. Module Contracts (DbC)

### 4.1 Loading, Merge & Validation

- **Runtime Backing:** `real-runtime` · **Verification Levels:** `unit`

- Preconditions: файлы §1.1 могут отсутствовать — валидное состояние (чистая авто-детекция, встроенные гейты).
- Postconditions:
  - Merge строго по §1.2; per-key провенанс доступен `verify --plan`.
  - Фатальны только ошибки **этой** схемы: битый JSON/YAML файла и невалидная секция `stack`. Чужие top-level секции (`models`) валидируются своими потребителями — их проблемы не блокируют verify.
  - **Любая ошибка конфига фатальна** (stack.spec FR-STACK-12): битый YAML/JSON, неизвестный ключ на любом уровне известной схемы (включая опечатки — с подсказкой «did you mean»), неверный тип, невалидная duration-строка, неизвестный id в `use`, override несуществующего гейта. Команда сообщает **полный список** ошибок и завершает exit 4, не исполнив ни одного гейта. Запуск верификации по конфигу, который не понят, бессмыслен и опасен.
  - `extraGates` без `timeout` получает `10m`; без `outputMeansFailure` — `false`; без `sandbox` — `false`; override без поля наследует исходный гейт.
  - `sandbox` внутри `fixers` — ошибка конфига: fixer по определению исполняется в реальном дереве (stack.spec §4.4).
  - `env` мержится поверх `process.env` (переменная из конфига побеждает).
- Invariants: загрузка конфига не мутирует дерево и не исполняет команд; duration-строки — `<число><s|m|h>`.

### 4.2 E2E-покрытие

Механизм фикстур и схема `expect.yaml` — [`stack/e2e`](../e2e/e2e.spec.md); доктрина — [`infra-e2e`](../../infra-e2e/infra-e2e.spec.md). Набор конфига проверяет **семантику конфига**, а не реализацию гейтов: фикстуры используют тривиальный гейт (`argv: [true]`), чтобы падение указывало на конфиг, а не на тулчейн. Команда — `test:e2e:config`, тулчейн — только `git`.

| Фикстура                    | Состояние фикстуры                                        | Ожидание                                                             |
| --------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------- |
| `cfg-none`                  | ни одного конфиг-файла                                    | чистая авто-детекция, встроенные гейты, exit 0                       |
| `cfg-yaml-only`             | только `gennady.yaml`                                     | значения применены, провенанс в `--plan` указывает на `gennady.yaml` |
| `cfg-deep-merge`            | `gennady.yaml` + одноключевой `.gennadyrc`                | остальное дошло из yaml; провенанс **per-key** различает источники   |
| `cfg-array-replace`         | `skipGates` в обоих файлах                                | массив из приоритетного источника **замещает**, не конкатенируется   |
| `cfg-empty-array-reenable`  | `skipGates: []` в `.gennadyrc` поверх проектного skip     | гейт снова исполняется (D-CFG-002)                                   |
| `cfg-home-rc`               | `$HOME/.gennadyrc` (подменённый HOME)                     | учтён с низшим приоритетом; провенанс называет файл                  |
| `cfg-broken-yaml`           | невалидный YAML                                           | `CONFIG_ERROR`, exit 4, **ни один гейт не исполнен**                 |
| `cfg-unknown-key`           | опечатка `skipGate`                                       | exit 4 + did-you-mean подсказка                                      |
| `cfg-unknown-plugin`        | `stack.rust`                                              | exit 4 + список известных плагинов                                   |
| `cfg-bad-duration`          | `timeout: 5min`                                           | exit 4 + грамматика duration в сообщении                             |
| `cfg-override-unknown-gate` | `overrideGates.nosuch`                                    | exit 4 + список встроенных гейтов                                    |
| `cfg-all-errors`            | три независимые ошибки в одном файле                      | все три в выводе (не только первая)                                  |
| `cfg-foreign-models`        | битая секция `models` рядом с валидным `stack`            | verify работает: чужая секция не фатальна                            |
| `cfg-use-narrows`           | `use: [golang]` в репозитории с `package.json` и `go.mod` | активен только golang                                                |
| `cfg-stack-flag-oneshot`    | `--stack=node` поверх `use: [golang]`                     | CLI-флаг действует как одноразовый `use`                             |

## 5. Module Decision Log

### D-CFG-001 — YAML для проектного файла, JSON для личных

- **Status:** active
- **Recorded:** spec review round 1, PR #5
- **Why:** комментарии в инфраструктурном конфиге обязательны (§1.1); `.gennadyrc` уже существует как JSON и уже gitignored из-за секретов. Парсер YAML — dev-dep c exact pin, бандлится Vite.
- **Rejected alternatives:** JSON для проектного файла (нет комментариев); un-ignore `.gennadyrc` (риск утечки ключей); TOML (ещё одна экосистема без выигрыша над YAML).

### D-CFG-002 — Deep-merge с per-key провенансом

- **Status:** active
- **Recorded:** spec review round 2, PR #5 — supersedes winner-takes-all из round 1
- **Why:** Winner-takes-all заставлял ради одного личного ключа вручную транслировать всю секцию из YAML в JSON — неприемлемый UX (ревью). Deep-merge по §1.2 (объекты рекурсивно, скаляры/массивы замещаются) + обязательный per-key провенанс в `--plan` снимает и UX-проблему, и претензию к дебажимости: «откуда взялся этот таймаут» отвечает сам план.
- **Risk accepted:** замещение массивов может удивить (личный `skipGates` не дополняет, а замещает проектный) — зато позволяет личным конфигом как расширять, так и сужать; правило одно и на виду.

### D-CFG-003 — Duration-строки, а не миллисекунды

- **Status:** active
- **Why:** `"10m"` читается и ревьюится; `600000` — нет. Go-подобный формат знаком целевой аудитории (backend).

### D-CFG-004 — Ошибки конфига фатальны

- **Status:** active
- **Recorded:** spec review round 2, PR #5 — supersedes «graceful degradation» из round 1
- **Why:** Прогон по непонятому конфигу — верификация не того, о чём просил пользователь: зелёный результат с проигнорированным конфигом хуже отказа. Все ошибки собираются и печатаются списком, exit 4 до исполнения гейтов (stack.spec FR-STACK-12).

### D-CFG-005 — Схема не версионируется

- **Status:** active
- **Recorded:** spec review round 3, PR #5 — supersedes «обязательный version» из round 2
- **Why:** Конфиг живёт рядом с инструментом и обновляется вместе с ним; отдельный `version`-ключ — boilerplate, который в ~каждом файле имел бы одно и то же значение. Строгая валидация (§4.1) уже делает несовместимость явной: неизвестный ключ/тип → полный список ошибок с подсказками, exit 4. Ломающие изменения схемы едут с релизами «Геннадия».
- **Rejected alternatives:** обязательный `version: 1` в `gennady.yaml` (round 2; отклонён на ревью как избыточный).
