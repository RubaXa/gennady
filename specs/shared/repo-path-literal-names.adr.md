# ADR: glob-метасимволы в имени существующего файла — точный путь

- **Статус:** принят
- **Дата:** 2026-11-02
- **Уточняет:** политику repo-path в `specs/shared/shared.spec.md` («pattern-free default») и
  нормализацию Target Files в `specs/cli/verify/verify.spec.md`
- **Issue:** #1, P1

## Контекст

Проверки путей отвергали любой путь со спецсимволами glob (`[`, `]`, `{`, `}`, `*`, `?`) ещё до
обращения к диску. Обычный отслеживаемый файл `pages/[...slug].tsx` — catch-all маршрут, такие
имена норма в Next-подобных роутерах — поэтому ломал:

- `verify --phase full` и `verify --plan`: Target Files полного прогона собираются из
  `git ls-files`, нормализатор падал с `VERIFY_CONFIG_INVALID_TYPE` ("is not an exact repo-relative
  path"), код выхода 4. Пользователь не задаёт этот список и не может исключить из него путь;
- `sdd-verify --task … --phase …`, `sdd-task`, `sdd-check` и coverage, когда такой файл стоит в
  Target Files или File Mapping (общий инспектор `inspectRepoPath`);
- `rules resolve --files pages/[...slug].tsx`: путь уходил в fast-glob как маска, и `[...slug]`
  превращался в класс символов — совпадал с `pages/s.tsx`, а не с самим файлом.

## Решение

Glob-метасимволы буквальны только в имени существующего обычного файла внутри репозитория. Для пути,
которого нет на диске (или который указывает не на обычный файл), те же символы — маска, и проверка
отвергает её прежней ошибкой: `path must be exact, not a glob` в `inspectRepoPath`,
`VERIFY_CONFIG_INVALID_TYPE` "is not an exact repo-relative path" в `normalizeTargetFiles`.

| Место                                                                       | Поведение                                                                                                                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inspectRepoPath` (`shared/common/repo-path.ts`)                            | существующий обычный файл — точный путь в обоих режимах; `literal-brackets` дополнительно оставляет `[`/`]` буквальными в отсутствующем пути            |
| `normalizeTargetFiles` (`shared/verify/planning/normalize-target-files.ts`) | существующий обычный файл — точный Target File; отсутствующий путь с glob-синтаксисом — прежняя ошибка                                                  |
| `normalizeScope` (`shared/verify/planning/resolve-multistack.ts`)           | удаление в `changed`-скоупе пришло из VCS diff и остаётся буквальным; авторский `files`-скоуп и SDD tombstones сохраняют запрет для отсутствующих путей |
| `rules resolve --files` (`cli/cmd/rules/rules-resolve.ts`)                  | существующий обычный файл передаётся как есть, без fast-glob; отсутствующий ввод с glob-синтаксисом раскрывается как маска                              |

Остальные проверки — абсолютный путь, `..`, выход за корень, symlink-компонент, не-обычный файл —
не меняются и срабатывают раньше проверки glob-синтаксиса.

Внешние инструменты получают путь как отдельный argv-элемент без shell. Prettier и ESLint 10.9
(версии из `package.json` этого репозитория, проверено 2026-10-30) при существующем файле
`pages/[...slug].js` обрабатывают ровно его и не раскрывают имя как маску: соседний `pages/s.js` в
выборку не попадает. Для других инструментов и версий это не проверялось.

## Отвергнутые альтернативы

- **Экранировать `[`/`]` в тикетах и спеках.** Список полного прогона приходит из `git ls-files`, его
  никто не пишет руками; экранированная строка расходится с реальным именем файла.
- **Выбрасывать такие файлы из полного прогона.** Тихо пропускает реальный код.
- **Включить `literal-brackets` у всех вызывающих.** Фигурные скобки и `*` в существующих именах
  остались бы ошибкой.

## Принятый риск

Файл с буквальным `*` или `?` в имени теперь принимается как точный путь. Раскрытия маски это не
даёт: проверка подтверждает ровно один существующий обычный файл с этим именем.

## Доказательство

- `ai/flow-eval/__tests__/pilot-verify-probe.test.ts` — настоящий source CLI: маршрут со скобками
  проходит полный gate так же, как обычный (GREEN для RED из issue #1);
- `shared/verify/__tests__/multistack-planner.test.ts` — план `all`/`files` с `pages/[...slug].tsx` и
  `a/{b}.ts`; удаление из `changed` остаётся буквальным; отсутствующие маски отвергаются;
- `cli/cmd/sdd-verify/__tests__/phase-context.test.ts` — фаза с такими Target Files проходит,
  отсутствующий путь-маска отвергается;
- `cli/cmd/_shared/__tests__/sdd-coverage.test.ts` — `inspectRepoPath` для обоих режимов;
- `cli/__tests__/tool-behavior/rules.test.ts` — `rules resolve --files` читает файл буквально.
