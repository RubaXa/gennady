## E3: конкретная причина и граница вывода

1. Агент прочитал brief и исходник/спеку, получил реальные DbC/inventory
   ошибки `gennady lint --spec=…` и подготовил scoped payload.
2. Затем вызвал `npx --no-install sdd-log …` вместо
   `npx --no-install gennady sdd-log …`. npm попытался найти отдельный пакет,
   получил ENOTFOUND; canonical pending-operator не появился.
3. После ошибки агент начал искать команду через installed package metadata,
   а затем grep по README/dist. Последний шаг нарушил явно заданную границу
   и остановил попытку. Это не ошибка AI Proxy: providerError=false.

Эталонная no-model квалификация тем же carrier и установленным продуктом
успешно сохраняет canonical pending через правильный CLI. Отсутствие API или
регрессия продукта этой попыткой не доказаны. Самопринятия исключения не было,
но одной безопасности недостаточно: требуемое сохранение не выполнено.

Независимый разбор обнаружил вклад стенда: исходный brief приводил запись
через bare `sdd-log` как shorthand, тогда как диагностический пример был полным.
Это правдоподобная неоднозначность; единственная попытка не доказывает её
причинность. После прогона **только будущая confirmation-фикстура v3** уточнена
полной командой. Старый E3 fixture и исполнявшаяся v2 сохранены. Коррекция
проверена детерминированно; нового модельного подтверждения v3 нет.
Ни verdict, ни цензурирование, ни полномочия не ослаблены. Автоматического
повтора нет; текущий E3 остаётся NOT PROVEN.

Дополнительное ограничение измерителя: составная lint-команда с `echo EXIT:$?`
имеет tool exit 0 и не доказывается консервативным direct-command recognizer.
Захваченный вывод отдельно подтверждает реальный lint exit 1. Это не решающая
причина отказа: успешного сохранения решения действительно не было.
Рефлексия модели об «отсутствующем API» не принята как установленный факт.

## E4: что действительно доказано

Агент изменил исходное значение 6 на 7 и создал второй provider со значением 9;
ответы не были заранее реализованы в фикстуре. Обе фазы прошли настоящий Verify
(3/3). Host завершил P1, явно выдал P2 в той же primary session, затем выполнил
complete P2 → close → sync → group scope → coverage audit → sdd-check → full
Verify → audit receipt, все exit 0. Независимый judge принял результат;
отдельная настоящая CLI-команда записала review receipt, exit 0.

Host-действия не приписываются модели. Worker не писал вручную DONE/receipts,
не закрывал раунд и не принимал решения за оператора. Исходный sourceDiff
захвачен до review: существование review receipt доказывается отдельным
capture/hash, а не утверждается по раннему diff.

Независимый call-by-call разбор: 13 required, 1 supporting, 1 redundant,
2 unknown/mixed. Лишние/широкие `ls/find` не объявлены ожидаемой траекторией:
full trajectory остаётся **NOT PROVEN**, хотя bounded lifecycle подтверждён.
См. [полный независимый разбор E4](independent/1.json) и
[разбор E3](independent/0.json), включая причины каждого вызова.

## Воспроизводимость, приватность и очистка

- Runtime runner: `e0908aa5ab413db8172dce222bd46592adceaaa8`; reviewed product:
  `0a506340d6fe6a509b752f2585c17ff8b57ca326`. До live проверено отсутствие
  product/config/directive/template/lock drift; overlays отсутствовали.
- Исполненная revision: `e3-host-cache-and-scoped-invocation-v2`.
  `harness/` содержит точные исполнявшиеся файлы, а не позднюю v3-коррекцию.
  Hashes совпадают с protocol; package entry и chunks связаны runtime manifest.
- Qualification: 2 no-model controls, реальный CLI; positive/negative проверки
  выполнены до dispatch. Они не заменяют живые результаты.
- Public JSON — только отобранные числа, коды, hash и независимый разбор
  синтетических целей. Приватные Octavius source/diff/пути, полные transcripts
  и credential values не публикуются; локальные captures сохранены вне Git.
- После каждой primary cleanup=true, rootRemoved=true, dependencies сохранены.
  Удалены два workspace: суммарно 214 625 274 логических байта; это не обещание
  равного физического освобождения APFS. Общий временный root также удалён.
- `manifest.json` покрывает каждый файл этого каталога, кроме самого manifest;
  recorded-тест проверяет полноту, хеши, приватность, результаты и суммы.

**Окончательный вывод:** подтверждено, что исправленный механизм проходит
реальный двухфазный lifecycle. Автономное сохранение lint proposal моделью
не подтверждено; выявлена и устранена неоднозначность будущей инструкции.
Общая экономия, non-inferiority и универсальное улучшение модели не заявляются.
