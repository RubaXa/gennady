# TOOLFACT1: факты от инструмента сокращают расход, но пакет отклонён

**Решение: не включать экспериментальный ответ `sdd-new` по умолчанию.**
Расход снизился, однако пять кандидатных документов имеют конкретные смысловые противоречия.
Критерий «дешевле без потери качества» не выполнен. Директивы и рабочий CLI не меняем;
реализация сохранена в экспериментальной ветке и [полном diff](variants/facts/from-frozen-source.diff.txt).

на сценарий, последовательно. Только `llm-proxy/deepseek-v4-flash` через AI Proxy.
Контроль `b30093dc`, кандидат `8bf28d29`; оба clean. Старые результаты не использованы как контроль.
Одинаковы задания, оценщик v5, харнесс, зависимости, конфигурация и тексты инструкций.
Сборки различаются намеренно: изменён именно ответ настоящего CLI.

## Что проверялось и что произошло

Единственная экспериментальная переменная — вычисляемый блок в ответе `sdd-new module`:
реальный Spec ID/ACR, синтаксис REQ/DL, точная относительная ссылка на существующую scope-спеку,
её реальные SECTION anchors и наблюдённые родительские IDs. Без ответов на предметную задачу,
придуманных требований или истории решений. Созданные skeletons побайтово одинаковы.

`ai/directives/**`, `ai/kit/templates/**` и `shared/sdd/templates.ts` не изменены.
Static instruction envelope не вырос. Динамический ответ инструмента вырос на 923/944 байта;
все 24 create-вызова имеют наблюдённый exit 0 и полный output fingerprint.

Всего вызовов: **305→260**, worker non-cache tokens: **641 633→571 973**.
У контролей наблюдаются две завершённые native записи target, у кандидата — одна (12/12 с каждой стороны).
Рефлексия связывает дополнительные записи с `SDD_REQ_ACRONYM_MISMATCH`, но это self-report,
не сохранённый diff промежуточных версий. Некоторые рассказы агента о числе Edit ошибочны:
приоритет у фактической траектории. Нельзя доказать, что именно повторная запись исправила семантику.

Наблюдаемые lexical-категории поиска, не автоматический вердикт «лишний вызов»:

| Сценарий  | ACR-поиски | Decision Log-поиски | `ls/find` discovery | Native чтение scope-спеки |
| --------- | ---------: | ------------------: | ------------------: | ------------------------: |
| Обычный   |        9→3 |                 8→6 |               26→21 |                       6→6 |
| Вложенный |        2→3 |                 4→3 |               16→15 |                       5→6 |

Кандидат читал родителя во всех 12 попытках: ухудшение нельзя объяснить доказанным пропуском этого чтения.
Native чтение root owner даже выросло: 1→2 / 2→4. Факты не устранили всю археологию.
Агенты отдельно отмечают, что вычисленные ID и ссылки помогли; рефлексия — диагностика, не grading authority.
Полные последовательности и каждый call: [контроль](report-v1/baseline.calls.md),
[кандидат](report-v1/facts.calls.md), [категории с call IDs](mechanism.json).

## Качество: реальные ошибки отдельно от ошибок оценщика

Все пять semantic FAIL находятся у кандидата; первичные verdict/rationale сохранены:

| Попытка, индекс с нуля       | Противоречие                                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| flat r1 (1), r3 (9), r4 (12) | «Есть хотя бы один ASCII-символ» допускает смешанный `"aé"`; другой REQ требует TypeError для любого не-ASCII. DbC имеет другое условие.             |
| nested r4 (14)               | Положительное условие одновременно требует ASCII-букву и запрещает всё вне пробела/underscore/hyphen; допустимые родителем `"a1"`/`"foo!"` теряются. |
| nested r6 (22)               | Постусловие запрещает крайний hyphen, хотя разрешённые `" -a"`/`"a-"` должны сохранять его по исходному контракту.                                   |

Первичный structural результат: flat 6→5 PASS, nested 5→6 PASS. Два отказа — дефекты стенда:
он не принимал «операторское подтверждение отсутствует» (1) и запятую после «одобрение не получено» (7).
Отдельный versioned v6 replay воспроизвёл v5 raw grades **48/48** и изменил только `pending-approval`
в этих двух документах (два режима reference). После этой механической калибровки structural 24/24.
**Semantic 12/12→7/12 не переписан.** Новых модельных вызовов при replay нет; все 48 фикстур удалены.
См. [калибровку](recalibration/calibrated-v6-replay.json).

Path proof остаётся 0/24: opaque Bash не позволяет доказать whole-write-only историю.
Это unknown, не PASS и не новое качество FAIL. Наблюдаемые native записи не доказывают отсутствие иных мутаций.
Не заявляем cost per compliant success с недоказанным знаменателем.
Старый static-prompt-compression comparator оставлен без изменений; его вывод не перекрашен в PASS.

## Расход серии и очистка

58 мин 46,5 с live-серии; подготовительные/финальные проверки отдельно.

| Роль              | Non-cache tokens | Cache-read tokens | Assistant messages |
| ----------------- | ---------------: | ----------------: | -----------------: |
| Worker            |        1 213 606 |        11 701 760 |                383 |
| Независимый судья |          356 853 |            49 152 |                 24 |
| Рефлексия         |          920 421 |            49 152 |                 24 |
| Всего             |        2 490 880 |        11 800 064 |                431 |

Все 72 role usage измерения complete/Flash-qualified. Денежная цена и точное число HTTP/retries
неизвестны; SDK `cost=0` не означает бесплатность. Вызовы инструментов и assistant messages — не HTTP requests.

После **каждой** попытки сохранены compact primary bytes, затем удалены её fixture, SDK-сессии и inactive
dependency store. Всего 24 fixture cleanup и 48 deletion acknowledgements, ошибок 0.
Собственный сервер на 4200 остановлен по bound PID/start/cwd; десять private state/cache roots удалены,
права журналов восстановлены. Общие зависимости сохранены; в каждый прогон они не копировались.
Повторяемый офлайн replay пяти существующих CLI — byte-equal; replay scratch удалён.
См. [cleanup proof](cleanup-proof.json), [portable replay](replay-proof.json),
[протокол](protocol/REPEAT-CONTRACT.md), [технические оговорки](protocol/OPERATIONAL-NOTES.md).

Подход к разбору workflow по фактическим tool traces соответствует
[методике trace grading](https://developers.openai.com/api/docs/guides/trace-grading).
Рабочий вывод ограничен этим Flash pilot: гипотеза экономии подтверждена по расходу,
но весь пакет отклонён из-за наблюдаемой регрессии качества. Это не запрет фактов в инструментах вообще.
