# CONTRACTCUE1: экономия сохранилась; общий критерий не пройден

24 **новых** live-попытки, `llm-proxy/deepseek-v4-flash` через AI Proxy.
Плоский и вложенный модули × контроль/кандидат × 6 повторов. Источники:
`ddd26bd88a4b80389faf95e2533766ae44e6f84f` →
`bab3ecc8579bf6a7603fed71df75b3b7922bbe3c`.
Оба используют один frozen `calibrated-v6`; директивы, шаблоны, brief, родитель,
oracle, harness, модель и бюджеты неизменны. Порядок пар AB/BA заморожен до запуска.

**Решение:** положительный пилот для плоского модуля, более слабая экономия для
вложенного; **полный пакет не выбран для production**. Во вложенном сценарии не
достигнуто заранее заданное снижение worker-токенов ≥10%; одна смысловая ошибка
кандидата осталась, полный path-пруф не получен. Автоматического принятия/merge нет.
Промпты/CLI по умолчанию не изменены. Не включать вариант только для знакомой
глубины каталога: такая benchmark-specific развилка не проверялась.

## Что произошло в прежних пяти неудачах TOOLFACT1

Это разбор фактических документов, а не пересказ догадок worker. Точные цитаты,
SHA-256 документов/судей/рефлексий/траекторий и call IDs:
[five-failure-analysis.json](./five-failure-analysis.json). Оригинальные оценки не менялись.

| Случай TOOLFACT1    | Ошибка документа                                                         | Конкретное противоречие                                                                                                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| flat r1, index 1    | «вся строка ASCII» заменено на «содержит хотя бы один ASCII-символ»      | `fooé`: положительное требование велит нормализовать, отрицательное — бросить `TypeError`. Более строгий DbC не задаёт приоритет требований. Отдельная жалоба старого oracle на pending была ложной и уже исправлена v6; это не отменяет противоречия требований. |
| flat r3, index 9    | Потеря того же универсального ограничения в Trigger                      | `aé` одновременно удовлетворяет NOR-REQ-1 и условию отказа NOR-REQ-2; DbC Pre исключает такой вход, но расходится с Trigger.                                                                                                                                      |
| flat r4, index 12   | Родительский ASCII-only домен расширен при переформулировке              | `aé` требует и возврата, и исключения. В исходном TOK-REQ-1 этого пересечения нет.                                                                                                                                                                                |
| nested r4, index 14 | Придуман более узкий допустимый алфавит; формулировка сама противоречива | Требует букву, но разрешает только пробелы/underscore/hyphen. Теряются допустимые `a1`, `foo!`; даже собственный пример `Foo__BAR` не удовлетворяет Trigger.                                                                                                      |
| nested r6, index 22 | Добавлена несуществующая гарантия Post                                   | Обещает отсутствие `-` по краям. Но `" -a"` по родительскому алгоритму даёт `"-a"`, а `"a-"` остаётся `"a-"`. Убирать крайние дефисы никто не требовал.                                                                                                           |

Все пять **прочитали родительскую спеку до записи**. Поэтому утверждение
«не читали родителя» опровергается трассами. Проблема — перенос смысла между
родительским контрактом, локальным Trigger и DbC, не отсутствие ID/ссылок.
Рефлексии чаще подозревали Handoff/формат/имена сценариев и не называли реальное
противоречие; самоотчёт не заменяет проверку документа.

В прежнем контроле были две записи на попытку, а у TOOLFACT1 одна. Это корреляция,
не доказательство пользы переписывания: промежуточные тела файлов не сохранялись.
В текущем свежем контроле тоже возникли ошибки домена/DbC. Следовательно, пяти
предыдущих неудач недостаточно, чтобы причинно приписать дефект именно фактам.

Дополнительный возможный источник путаницы: существующий
`module-spec-structure.xml#MODULE_REQUIREMENTS` запрещает копировать родительские
требования и говорит о «narrower obligation». Авторы переформулировывали родителя
как локальное уточнение. Это наблюдаемое совпадение плюс сигнал из рефлексии,
**не установленная причина**; формат не менялся во время эксперимента.

## Одна новая гипотеза

В tool-output оставить прежние вычисленные ID/ссылки/REQ-DL syntax и добавить
короткую generic-проверку **до финальной записи**:

```text
compare(scope Trigger/When, local Trigger/When, DbC Pre/Post)
retain every input-domain qualifier
changed domain / stronger guarantee: only if explicitly required by brief
try one boundary witness per changed condition; resolve conflicts before Write
```

Ни `ASCII`, ни конкретного нормализатора, ни готовых контрпримеров в этой подсказке
нет. Родительский нормативный текст не копируется в вывод. Директивы/шаблоны не
увеличены; добавлено 465 байт к прежнему tool-output пакету. Полная добавка к
контролю — **1388/1409 байт** для flat/nested. Созданные skeleton bytes одинаковы:
[доказательство реальным собранным CLI](./protocol/tool-output-proof.json).

Сравнивается **переработанный пакет против свежего исходного контроля**, а не
изолированная добавка cue против одновременно запущенного TOOLFACT1. Исторические
прогоны — диагностика, не свежий третий arm. Это ограничивает причинные выводы.

Медианы шести повторов; время — работа автора, не judge/reflection/весь запуск.
Токены — worker non-cache input + output + reasoning; cache учтён отдельно.

| -------- | -------------------------------: | ---------------------: | ---------------: | ----------------------------: | ---------: | -------------: |
| flat     | 57 721,5 → 47 146,5 (**−18,3%**) |   29 → 20 (**−31,0%**) |        17,5 → 15 |  100,793 → 90,841 (**−9,9%**) |  5/6 → 6/6 |  **4/6 → 6/6** |
| nested   |  49 700,5 → 45 868,5 (**−7,7%**) | 25 → 22,5 (**−10,0%**) |      19,5 → 16,5 | 103,969 → 84,276 (**−18,9%**) |  5/6 → 6/6 |  **5/6 → 5/6** |

Суммарно вызовов **318 → 261**; worker non-cache **645 316 → 584 519**.
Это не обещание экономии в каждом повторе: flat r3 вырос по calls/time, nested
r3/r4 — по tokens/calls/time. Все повторы, включая неудачные и дорогие, сохранены.
См. [диапазоны и каждую пару](./report-v1/net-effects.json),
[raw counters](./report-v1/raw-metrics.json),

шесть повторов — пилот. У standard comparator другой, прежний критерий сжатия
статического контекста; его результат не подменяется новым net-cost критерием.

### Все текущие неудачи и спорная проверка

- Candidate nested r1, index 3: в MODULE_REQUIREMENTS ASCII-only сохранён, но
  DbC Pre вновь допускает смешанное `fooé`; соседнее условие требует исключение.
  Это реальное противоречие; общий reminder не гарантирует согласованность секций.
- Baseline nested r2, index 7: потеря ASCII-only в Trigger плюс Post «только буквы
  и hyphen», противоречащий допустимому `x1`.
- Baseline flat r3, index 9: DbC Pre допускает пустую ASCII-строку, а Post обещает
  результат при одновременном условии бросить `TypeError` для пустого входа.
- Baseline flat r6, index 20: неправильная ссылка `../../token.spec.md` ведёт в
  отсутствующий `specs/token.spec.md`. Требования сами по себе корректны.
- Baseline nested r5, index 18: semantic PASS, но frozen механический
  `pending-approval` FAIL. Handoff говорит, что детали `still need operator
confirmation before scaffold`, без явного pending owner-status. Judge оспаривает
  oracle. Это **спорная лексическая граница**, а не доказанная семантическая
  регрессия. Оценщик не перенастраивался; raw FAIL сохранён. Переход 5→6 по форме
  nested не выдаётся за доказанное содержательное улучшение.

## Что изменилось в траектории

Ниже — лексические категории наблюдаемых вызовов, не полная классификация их
необходимости и не чтение внутренних рассуждений модели.

| Категория за шесть повторов      | flat: контроль → кандидат |    nested |
| -------------------------------- | ------------------------: | --------: |
| Поиск источника acronym          |                     5 → 1 |    10 → 6 |
| Поиск Decision Log syntax        |                     6 → 1 |     5 → 9 |
| `ls/find` discovery              |                   20 → 21 |   23 → 20 |
| Полное чтение root directive     |                     1 → 1 |     2 → 2 |
| Native чтение родительской спеки |                     6 → 5 |     5 → 6 |
| Всего вызовов                    |                 165 → 122 | 153 → 139 |

Native Read — не единственный способ прочитать файл; ноль такого вызова не
доказывает пропуск источника. Все 24 создания модуля наблюдались с exit 0 и
полным префиксом вывода. [Категории, call IDs, exit/output evidence](./mechanism.json).
Полные наблюдаемые timelines:
[контроль](./report-v1/baseline.calls.md), [кандидат](./report-v1/facts.calls.md).

Все 12 candidate сделали одну завершённую native-запись; контролю понадобилось
по 2–3. Это не доказательство, что дополнительные записи всегда бесполезны.
Полный M3/path-пруф **unknown у всех 24**, в том числе из-за opaque shell-путей;
отсутствие лексической категории opaque Bash не является полным path-proof.
Запрет на выдуманный зелёный path и criteria native-write не ослаблены.

Outlier nested candidate r4 (33 calls / 78 358 tokens) искал
`Approval`/`authoring-complete`, читал root/router/scope и дополнительно проверял
статус после записи. Данные о синтаксисе он уже получил: их выдача не устранила
всю путаницу маршрута/границы завершения. Это объяснение наблюдаемой работы,
не причинное доказательство того, что cue вызвал дополнительные поиски.

## Что оставляем

- Оставляем **положительный результат пилота и воспроизводимый прототип** для
  дальнейшего review; не выдаём единичный удачный прогон за успех всей гипотезы.
- Не принимаем общий пакет в production: nested не достиг 10% token target, одна
  смысловая ошибка не устранена, полный path-proof отсутствует. `positiveBothCases=false`.
- Не делаем вывод «готовые факты вредны»: текущий контроль сам ошибался. В этой
  серии revised packet экономил медианные ресурсы в обоих сценариях, не увеличив
  число наблюдаемых смысловых FAIL. Изолированный эффект cue этим дизайном не доказан.
- Следующее направление **только как непроверенная гипотеза**, не новое обещание:
  убрать повторное свободное изложение одного домена в Trigger/Pre/Post, оставив
  источник контракта и явные module-owned delta; отдельно устранить неоднозначность
  границы authoring. Не смешивать эти две переменные в очередном прогоне.

## Очистка

Перед удалением **каждой** песочницы сохранены документ, trajectory, summary,
judge, reflection. Все 24 owned case roots и inactive dependency stores удалены,
48 SDK-session delete acknowledgements сохранены. Свой сервер на 4201 остановлен;
все 10 приватных каталогов удалены; права source-журналов восстановлены.
См. [cleanup proof](./cleanup-proof.json), [runtime finalizer](./runtime-cleanup-summary.json).
После проверки portable archive удаляются оба собственных worktree и весь runtime root;
commit refs и общий физический node_modules сохраняются. Чужие worktree/кэши не трогаются.
Итог отсутствия runtime root фиксируется отдельно после обязательных Git hooks.
