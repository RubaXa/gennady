# SC3: lifecycle и производительность

Статус: квалификация перед независимым SC3 review. Живых вызовов модели: **0/8**;
SC4 не начат, Draft PR #131 не разрешён к merge.

`cli-performance.json` — первоначальный actual compiled CLI замер;
`cli-performance-final.json` — промежуточный повтор после formatting/contracts;
`cli-performance-lifecycle.json` — итог после bootstrap-format qualification, с хэшами shared parser
и source-format policy. Все выполнены над изолированными копиями Octavius; прежние отчёты не перезаписаны.
Отдельно представлены первый процесс (не OS-cold cache), пять последующих процессов,
elapsed/CPU/RSS и явные adapter read counters. Внешняя модель не получает исходники.
Source overlay и compiled hashes привязывают замер к локальному кандидату, а не только к parent SHA.
Фазовый запрос проверяет один исходник среди тысяч деклараций; это не полный аудит проекта.

Сравнивать с SC2 можно только описательно: host/cache отличаются, ускорение не утверждается.
Существенные acceptance — отсутствие полного source-walk у узкой фазы, реальные ошибки владения
после гейтов, неизменность оригинального checkout и удаление собственной временной копии.
