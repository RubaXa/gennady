# Журналы и разборы

Здесь лежит **история** eval-работы: журналы экспериментов, постмортемы реальных прогонов, roadmap. Это
**записи, а не инструкции** — как выполнять работу, описано в основной документации
([`../README.md`](../README.md)). Сюда заглядывают, чтобы понять, _почему_ что-то сделано именно так и
что уже пробовали.

## Зачем это ведём

- **Не повторять отклонённое.** Каждый неудачный путь записан с причиной — чтобы его не пробовали заново
  (дисциплина both-outcomes из [`../07-EXPERIMENTS.md`](../07-EXPERIMENTS.md)).
- **Доказательства решений.** Принятые решения ссылаются на реальные прогоны и файлы, а не на память.
- **Передача контекста между сессиями.** Работа шла долго и в несколько заходов; журнал держит нить.

## Что поддерживать, а что заморожено

| Файл                                                                                   | Что это                                               | Обновлять?                                                       |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------- |
| [`EXPERIMENTS-LOG.md`](./EXPERIMENTS-LOG.md)                                           | Журнал гипотез и их исходов.                          | **Да** — дописывать при каждом новом эксперименте (append-only). |
| [`flow-verification-ledger.md`](./flow-verification-ledger.md)                         | Подтверждено / отклонено / принято / внедрено.        | **Да** — дописывать при новых находках и решениях.               |
| [`ROADMAP.md`](./ROADMAP.md)                                                           | План работ и статусы целей.                           | По мере продвижения; это снимок направления.                     |
| [`PROGRESS-REPORT.md`](./PROGRESS-REPORT.md)                                           | Отчёт «было → стало» для коллег.                      | Снимок момента; обновлять при крупных вехах.                     |
| [`flow-verification-redesign.md`](./flow-verification-redesign.md)                     | План редизайна проверки результата фаз.               | Заморожен как исторический план.                                 |
| [`roundtrip-wall3-assessment.md`](./roundtrip-wall3-assessment.md)                     | Разбор round-trip cloud-ios (три «стены»).            | Заморожен как постмортем.                                        |
| [`swiftlint-setup.md`](./swiftlint-setup.md)                                           | Разовая настройка хоста под SwiftLint-бенч.           | Обновлять, только если меняется процедура.                       |
| [`infra-tasks-research.md`](./infra-tasks-research.md)                                 | Ресёрч инфра-задач под фикстуры.                      | Заморожен как ресёрч.                                            |
| [`p9-signifiers.md`](./p9-signifiers.md), [`p9-verification.md`](./p9-verification.md) | Калибровка и вердикт отдельного раннего прогона (P9). | Заморожены как исторические записи.                              |

Правило простое: **живые журналы** (EXPERIMENTS-LOG, ledger) дописывают; **снимки** (ROADMAP,
PROGRESS-REPORT) обновляют по вехам; **постмортемы и ресёрч** не трогают — они фиксируют момент.

Не создавай новые файлы-разборы без нужды: результат эксперимента почти всегда — это дописанная строка в
EXPERIMENTS-LOG и/или ledger, а не отдельный документ.
