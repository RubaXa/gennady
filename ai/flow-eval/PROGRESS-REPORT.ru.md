# SDD v2 flow: отчёт о прогрессе (было → стало)

Отчёт для коллег: с чего начали, где флоу не работал / был избыточен, какие проблемы нашли, что
стало по факту и почему это прогресс. Все числа — из eval-логов и recovery-анализа (`ai/drafts/
research/sdd-v2-rc-recovery/`), не по памяти; спорные помечены.

> Терминология: **eval** гоняет реальную дешёвую модель (`deepseek-v4-flash`) через фазу SDD как
> обычного разработчика в изолированной песочнице. Меряем **двумя измерениями**: вердикт LLM-judge
> (стохастичен) и **механику** — `gennady sdd-check --all` / `sdd-verify` (источник истины).

| --------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Полный greenfield-цикл (authoring→scaffold→execute) | не проходил; сессия **зациклилась** (~12 ч, 15+ прогонов, десятки незакоммиченных файлов) | проходит **механически end-to-end** (тикет DONE, `sdd-verify P2` ✅ 3/3, coverage 100%, тесты зелёные) |
| Чистота авторинга (свежий прогон)                   | ~**1/4** чисто                                                                            | **5/6** чисто (посл. последовательный батч **3/3**)                                                    |

| Причина провалов                                    | флоу «пережат» + дефекты фикстур/судьи                                                    | 9 детерминированных дефектов инструмента/шаблона/фикстуры сняты и залочены тестами                     |

**Главный вывод:** большая часть «нондетерминизма модели» оказалась **детерминированными дефектами
инструмента и шаблона** — шаблон местами велел модели делать неправильно, а проверки отвергали
санкционированные самим же шаблоном формы. Сняли зажимы → предсказуемость выросла измеримо.

## 1. С чего начали: где и почему флоу не работал

Исходная RC-сессия зацикливалась на всех трёх фазах. Три одновременные причины (из adversarial-аудита
02 и итогового отчёта 08):

1. **Флоу был избыточен / «пережат».** Директивный стек: ~37 аксиом «подключены, но не активированы» в
   шагах; на дешёвой модели ~10 мин до первого артефакта; ~70% чтения приходилось на директивы и лишь
   ~23% на форматы. Каскад правил рвался (TS-правило P1 не наследовалось). _(числа — из 02/08, порядок
   величины)_
2. **Дефектные фикстуры/судья давали ложные вердикты.** `parseVerdict` читал `Verdict: PASS` как fail;
   diff пропускал untracked-файлы; coverage-профиль протекал через `NODE_TEST_CONTEXT`.
3. **Пробел спецификации.** scaffold пропускал неутверждённые планы; владение bootstrap-предусловий не
   было определено.

**Пример «пережатости» дословно:** скелет велел писать `No external bootstrap required.`, а валидатор
отвергал эту строку как неполную → next-hint гнал scaffold назад в authoring → застревание на границе
фазы.

## 2. По фазам: как проходил и что ломалось

### Authoring

- **Старт:** путаница границы фазы, застревание (bootstrap-блокер выше).
- **Ломалось в цепочке:** незаполненные плейсхолдеры скелета, которые проверки принимали за реальные
  ошибки — RESEARCH-ссылка `<yyyy-mm-dd>-<slug>`; caption с родительским `FIB-REQ-2`; и **баг скелета**
  `../../<scope>.spec.md` (неверная глубина для плоского модуля — модель честно писала как велено).
- **Сейчас:** свежие прогоны chain12a/b, chain14a/b/c — **чисто**; ни один снятый слип не вернулся.

### Scaffold

- **Ломалось:** worker тонул в чтении bootstrap/coverage-форматов — до **45** вызовов инструментов,
  выбивал бюджет; оставлял `<!-- BLOCKER -->`-подсказки в заполненных секциях.
- **Фикс:** M2.1 — coverage-подсказка в скелете (пример команды + «бери из лестницы, не сканируй») →
  нагрузка **45→33**.
- **Сейчас:** scaffold проходит (chain8/9/10b/11b — pass, `sdd-check --all` ✅ clean, тикет создан).

### Execute

- **Ломалось (детерминированно):** (а) c8 не провижнился → coverage структурно невыполним оффлайн;
  (б) мой инлайн-glob в `test:coverage` ломал receipt-фингерпринт `sdd-verify`.
- **Сейчас:** механически проходит **end-to-end** — chain10b: тикет `Status: [x] DONE`, P1+P2
  квитанции, **`sdd-verify P2` → ✅ ALL PASS (3/3)** + coverage, `npm test` 10/10. _(Ранний eval-«fail»
  execute был из-за неполной симуляции approval оператора — устранено: после полного approval judge даёт
  pass 2/2 на реальных артефактах.)_

## 3. Найденные проблемы → фиксы (все залочены тестами)

| Проблема                     | Симптом                                            | Фикс                                                                                | Тип             |
| ---------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------- | --------------- |
| Bootstrap «no external»      | скелет велит писать строку, валидатор её отвергает | `project-feasibility.ts` + `gate-queue.ts` принимают санкционированную пустую форму | зажим           |
| RESEARCH-плейсхолдер         | `<…>.research.md` считался битой ссылкой           | пропуск `<...>`-targets в link-резолверах (`targetIsScaffoldPlaceholder`)           | зажим           |
| caption cross-scope REQ      | родительский `FIB-REQ-2` в модуле отвергался       | флагать только REQ своего акронима                                                  | зажим           |
| скелет `../../` ссылка       | неверная глубина → битая ссылка                    | `templates.ts` → `../<scope>` + `build:directives`                                  | баг шаблона     |
| coverage: c8 не ставился     | `test:coverage` не создаёт отчёт оффлайн           | provision ставит c8 всем фикстурам                                                  | дефект фикстуры |
| coverage: glob в скрипте     | receipt-фингерпринт отвергает glob                 | `.mjs`-обёртка (один точный файл-токен)                                             | дефект фикстуры |
| coverage overload (scaffold) | 45 вызовов, выбит бюджет                           | M2.1 подсказка в скелете                                                            | избыточность    |
| judge `parseVerdict`         | `PASS` читался как fail                            | явный `VERDICT:` + без prose-догадок                                                | дефект судьи    |
| симуляция approval           | оставались `pending`-записи → judge падал          | полное approval (портал + Decision Log), `operator-approve.sh`                      | процедура       |
| mermaid-синтаксис            | невалидный `[F(n)]` без кавычек                    | **валидатор** даёт точную ошибку + топ-причины (не инструкция в промпте)            | инструмент      |

## 5. Куда пришли и почему это прогресс

- **Флоу рабочий.** Полный greenfield проходит механически end-to-end на дешёвой модели.
- **Предсказуемость измеримо выросла** (1/4 → 5/6 чистого авторинга; scaffold-нагрузка 45→33).
- **Каждый разрыв — детерминированный и залочен тестом**, а не «повезло с прогоном»: регрессия не
  вернётся молча.
- **Подтверждена гипотеза «пережат»:** из «нондетерминизма модели» большинство слипов оказались
  дефектами инструмента/шаблона (шаблон велел писать неверный путь; проверки не принимали свои же
  санкционированные формы). Правили на уровне **инструмента**, не промпта.
- **Инфраструктура закреплена:** eval задокументирован для любого разработчика
  (`ai/flow-eval/README.md`, `RUNBOOK.ru.md`, `WRITING-EVALS.ru.md`) — коллеги могут добавлять свои evals.

## 6. Что осталось (следующие ступени)
