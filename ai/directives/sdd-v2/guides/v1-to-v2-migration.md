# Миграция SDD v1 → v2

Детерминированный, верифицируемый runbook. План миграции — слой файлов `migration/`, который генерируется и проверяется тулом; исполнение идёт по нему. Запускать из корня проекта. Всё под git — откат всегда возможен.

> Когда нужно: `gennady sdd-state .` показал `FLOW_VERSION=v1` (есть `tasks/`) — роутер привёл сюда.

Легенда: 🤖 — детерминированный шаг (тул) · ✍️ — семантический (суждение агента, под гейтом) · ✅ — проверка · 🛑 — подтверждение оператора.

---

## Что меняется

- `tasks/<scope>/<module>/<m>.task-NN.md` → co-located `specs/<scope>/<module>/<m>.task.<ACR>-<slug>.md` + индексы `*.3-tasks.md`
- Task-ID: `TSK-NN` (или `<ACR>-NNN`) → `<ACR>-<slug>` (семантический)
- v1-тикеты получают `<!--SECTION:-->` якоря
- Секции спек — в целевой v2-порядок: Overview с обязательной диаграммой, заголовки без номеров, тяжёлые секции в `<details>`
- operator-текст → плоский инженерный русский

## Что НЕ трогаем

- `D-NNN` (decision-id, spec-local) — остаются
- `FR-NN` / `NFC-NN` / scope-префиксные требования — остаются
- `UTF-8`, `UTF-16` и пр. — это НЕ id, тул их не заменяет (замена только по точным ID со словогранью)

---

## Шаг 0 — скан 🤖 (без записи)

```bash
gennady sdd-state .                    # FLOW_VERSION=v1
gennady sdd-migrate plan --all .       # DRY-RUN: юниты (один на спеку), тикеты, orphan'ы
gennady sdd-migrate anchors --all .    # DRY-RUN: что заякорится / что уже
```

## Шаг 1 — слой плана 🤖

```bash
gennady sdd-migrate plan --all . --write
```

Появляется `migration/` (зеркалит `specs/`): по одному `*.migration.md` на спеку — сгенерированный Inventory (факты), карты для заполнения (Section Map / Ticket Map / Diagram Plan), чек-лист шагов юнита; плюс `migration/README.md` с общим порядком G1–G8 и таблицей юнитов.

## Шаг 2 — якоря 🤖

```bash
gennady sdd-migrate anchors --all . --write
gennady sdd-check --all .              # ✅ баланс якорей
```

## Шаг 3 — заполнить карты ✍️ (параллелится по юнитам)

Агент изучает исходник каждой спеки и заполняет её unit-файл: каждая секция источника → куда идёт (keep / rename / merge / split / drop), каждый тикет → новый `<ACR>-<slug>` (из `Meta.Purpose`, kebab-case, уникален в репо), Overview-диаграмма → из чего строится. Статус юнита → `MAPPED`.

```bash
gennady sdd-migrate plan --verify      # ✅ карты полны, слаги валидны и без коллизий, расхождений с реальностью нет
```

## Шаг 4 — подтверждение оператора 🛑

Оператор смотрит слой (карты, ID-map, что схлопнется) и даёт добро. Статусы → `APPROVED`. До этого ничего вне `migration/` не менялось.

## Шаг 5 — замена ID 🤖

```bash
gennady sdd-migrate ids . --from-plan            # DRY-RUN: сколько вхождений в каких файлах
gennady sdd-migrate ids . --from-plan --write    # замена по словогранице + гейт «ноль старых ID»
gennady sdd-check --all .                        # ✅
```

## Шаг 6 — структурный переезд 🤖 (по одному scope)

```bash
gennady sdd-migrate move . --scope <scope> --write
```

Тикеты переезжают (`git mv`), собираются `<module>.3-tasks.md` и `<scope>.3-tasks.md` из Meta тикетов, пустой `tasks/<scope>/` удаляется. Оба признака вместе (есть co-located индекс, нет `tasks/<scope>/`) переводят scope на v2 — с этого момента `sdd-check` проверяет его **строго** (flow определяется per-scope), соседи-v1 не шумят. Scope, у которого задач не было вовсе, остаётся мягким до конца миграции.

## Шаг 7 — реструктуризация спек ✍️ (параллелится по юнитам)

По Section Map каждого юнита: целевой порядок секций из `formats/*-spec-structure.xml`, заголовки без номеров, тяжёлое — в `<details>`, Overview с диаграммой по Diagram Plan; решения-дубли схлопываются (`compression.directive.xml`); текст — плоский технический русский.

```bash
gennady sdd-check --all specs/<scope>  # ✅ строгий v2: структура, фолды, разбор mermaid, языковой линт
```

Статус юнита → `DONE`.

## Шаг 8 — финальная верификация ✅

```bash
gennady sdd-state .                    # FLOW_VERSION=v2
gennady sdd-check --all .              # clean
gennady sdd-migrate ids . --from-plan  # DRY-RUN: заменять нечего (ноль старых ID)
```

Все юниты `DONE` → с подтверждения оператора удалить `migration/` (слой воплощён в репо; история — в git).

---

## Заметки

- Шаги 0–2, 5, 6, 8 — тулы; 3 и 7 — суждение агента, но по проверенному плану и под строгим гейтом `sdd-check`.
- Шаги 3 и 7 раздаются параллельно: unit-файл самодостаточен, юниты не пересекаются по файлам; общие механические шаги идут централизованно между ними.
- Заблокированный `move` (незаполненная карта, чужой тикет) останавливает только свой scope, не весь прогон.
