### Поведение (ступень 3 — диаграмма последовательности, новый поток выполнения)

```
 Клиент        SessionMiddleware      RedisStore        Redis
   │  запрос         │                    │               │

   │                 │◀───────────────────│               │

```

Как работает: сессия читается из Redis вместо памяти; при промахе — создаётся заново.

### Сценарии (ступень 4 — сценарий использования «зачем»)

```
Горизонтальное масштабирование (несколько инстансов)
        │
        ▼
  Сессия общая между инстансами  ──▶  RedisStore (постоянное, вне процесса)
        │
        ▼
  Сценарий: пользователь попал на другой инстанс за балансировщиком
            → сессия жива (раньше терялась с MemoryStore)
```

Зачем: MemoryStore не переживает несколько инстансов — Redis решает общий доступ к сессии. _(Источник: описание MR; сценарий заявлен автором.)_

### Разбор сущностей

**[E1] ✅ обоснован — `RedisSessionStore` (новый)**

Роль: реализация `SessionStore` поверх Redis — замена хранилища в памяти для горизонтального масштабирования.

Обоснование: автор заявляет «нужен для работы нескольких инстансов». Потребление реально — `SessionMiddleware` переключается на него через внедрение зависимостей. Аналогов в репозитории нет (`MemorySessionStore` — другая реализация того же интерфейса, не аналог). Граница на реальном разломе: постоянное против временного. Есть тесты.

Риск: 🟡 средний — вводит новую внешнюю зависимость (Redis), но интерфейс хранилища уже существовал.

---

**[E2] ⚠️ слабый — `config/redis.ts` (новый)**

Роль: модуль, реэкспортирующий `REDIS_URL` и `REDIS_PREFIX` из `process.env`.

Обоснование: значений два, объём минимален. Но в проекте уже есть `src/config/app.config.ts` с централизованным сбором переменных окружения — почему не добавить туда? Отклонение от конвенции без объяснения.

### Связи и риски

**[R1] ✅ оправдано — `SessionMiddleware` → `SessionStore` (интерфейс)**

Зависимость через интерфейс — классическое внедрение зависимостей, обе реализации взаимозаменяемы. Циклов нет. Направление: к стабильности (интерфейс стабильнее middleware).

**Оценка рисков:**

- 🎯 **Концентрация изменений:** основной код в `src/session/store.ts` (+120 строк). `middleware.ts` затронут минимально (+45/−12).
- 🧪 **Покрытие тестами:** `store.test.ts` покрывает `RedisSessionStore`. `middleware.ts` — без новых тестов (только правка импорта).
- 💥 **Радиус влияния:** `SessionMiddleware` зависит от `SessionStore` (интерфейс). Остальная система не затронута. См. [R1].
- 🖐 **Проверить руками:** переключение между хранилищами `Memory`/`Redis` через конфиг; проверка доступности при недоступном Redis; сериализация/десериализация сессий.
- 🚀 **Риски релиза:** новая зависимость `ioredis` в `package.json`; требуется Redis в dev/stage/prod; переменная окружения `REDIS_URL` обязательна — её отсутствие = падение при старте. Миграция сессий из памяти в Redis не предусмотрена.
- 📊 **Уровень риска:** 🟡 средний — одна новая внешняя зависимость, запасного варианта в памяти при отказе нет, добавлена проверка доступности.
