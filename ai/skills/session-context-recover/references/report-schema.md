# Recovery report

Present a readable report in this order:

1. **Located session** — provider, title, IDs, transcript, dates, workspace/worktree, branch, and whether those paths still exist.
2. **Current goal as understood** — concise actionable formulation.
3. **How the goal changed** — only material operator-driven changes.
4. **Confirmed completed work** — claims backed by evidence.
5. **Workspace binding** — approved absolute continuation directory, why it is authoritative, Git top-level, branch, HEAD, dirty files, and any differing caller/session cwd that must not be used.
6. **Stopping point** — last confirmed action, incomplete step, and interruption reason if known.
7. **Problems and contradictions** — include prior mistakes and unsupported claims.
8. **Verification queue** — disputed, unknown, or stale facts and exact proposed checks.
9. **Proposed continuation** — ordered steps, not yet executed.
10. **Operator decisions required** — minimal concrete questions.

For important claims use one status: `Confirmed`, `Likely`, `Disputed`, `Unknown`, or `Stale`. Cite transcript path plus line/message ID, or the current command/file observation. End with an explicit confirmation gate before mutation.
