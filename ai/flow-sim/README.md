# ai/flow-sim — симуляционная проверка SDD v2 флоу

Юнит-тесты покрывают `cli/cmd/*` и `shared/sdd/*` — детерминированный код. Директивы в
`ai/directives/sdd-v2/*.directive.xml` не код: они читаются и «исполняются» агентом-интерпретатором.
Единственный способ проверить, что `LOGIC_SWITCH` роутит куда должен, что `STOP` держит агента, и что
он не подхватывает директивы, которые не должен — живой прогон по фиксированному сценарию.

Полный протокол ролей (Executor / Verifier / Arbiter) и формат трейса — `PROTOCOL.md`. Карты
сценариев волны 1 — `scenarios/S<N>-<slug>.md`.

## Как запустить одну карту

Роль оркестратора (человек или управляющий агент):

1. Взять карту из `scenarios/`, вырезать секцию `## Checkpoints` — Executor не должен знать, что
   проверяют.
2. Выделить изолированную песочницу (временный каталог вне репозитория) и передать её путь Executor'у
   вместе с усечённой картой.
3. Executor собирает фикстуру по `## Fixture` дословно в этой песочнице, разыгрывает `## Entry` +
   `## Operator Script`, пишет `TRACE` по формату из `PROTOCOL.md`, останавливается на `## Stop`.
4. Verifier получает: полную карту (с Checkpoints), TRACE от Executor, `git diff` песочницы. Сверяет
   каждый Checkpoint с трейсом И с текстом директивы-первоисточника, выносит вердикт
   `CONFIRMED`/`VIOLATED` с уликой, отдельно — секцию «Импровизации».
5. При `VIOLATED` — Arbiter (отдельный ручной шаг) решает: дефект директивы (правится директива) или
   слабость исполнителя (сигнал упростить директиву).

## Куда пишутся трейсы

TRACE и `git diff` фикстуры — эфемерные, пишутся в scratch-директорию вне репозитория (путь даёт
оркестратор). В `ai/flow-sim/` коммитятся только карты сценариев и протокол — трейсы никогда.

## Связь с юнит-тестами

Юнит-тесты (`shared/sdd/__tests__/*`, `cli/cmd/*/__tests__/*`) проверяют инструменты изолированно —
`checkReadiness`, `parseScopes`, `sdd-new`, `sdd-check` и т.д. как функции/CLI с фиксированным
вводом/выводом. Карты здесь проверяют то, что юнит-тест не видит: правильную ли директиву агент
выбрал и загрузил, остановился ли там, где предписан `STOP`, и вызвал ли он ожидаемый инструмент
именно с ожидаемыми флагами (а не написал файл руками). Одно без другого не покрывает флоу целиком —
инструмент может быть протестирован идеально и всё равно вызываться из неправильной ветки.
