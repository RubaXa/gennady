## Почему задача остановлена, а не выполнена

Бриф Пачки 19 (`62-BATCH-QUEUE.md:270`) сузил T-B6-10 до двух файлов: `assembly-manifest.json`, `step-budget-gate.ts` — без `.hbs`-монолитов `infra`/`root`/`migration-v1-v2`/`router`, которые полная формулировка задачи на доске (`61-TASK-BOARD.md:153`) явно перечисляет как файлы, требующие lazy-split ("в т.ч. `infra` 9592 → lazy-split"). Тот же документ (`40-TRACK-DIRECTIVES-SKILLS.md:933-934`) прямо предупреждает: «единый лимит без предварительного lazy-split (T-B6-10) немедленно роняет билд на `infra` — T-B6-10 обязан идти раньше включения гейта на монолиты».

**Измерено, а не предположено.** Текущий `ai/kit/step-budget-gate.ts` (CLI-обёртка, строки 161-166) сканирует `ai/directives/sdd-v2/**` и **пропускает** любую директиву без соседней папки `<name>/steps/` — то есть любой монолит целиком:
```ts
const stepsDir = join(sddV2Dir, directive, 'steps');
if (!existsSync(stepsDir)) continue; // not lazily assembled yet — nothing to measure
```
Реальные токены (замерено `countTokens` из `shared/common/tokens.ts`, тем же способом, каким его использует сам гейт) по монолитам, у которых нет `steps/`:

| Директива | Токены | `SKELETON_TOKEN_LIMIT` (8000, hard) | `SKELETON_TOKEN_TARGET` (6000, soft) |
|---|---|---|---|
| `infra.directive.xml` | 9633 | **превышает на 1633 → error** | превышает |
| `root.directive.xml` | 7572 | в пределах | превышает на 1572 → warning |
| `migration-v1-v2.directive.xml` | 6741 | в пределах | превышает на 741 → warning |
| `router.directive.xml` | 6094 | в пределах | превышает на 94 → warning |

Текущий прогон гейта на реальном дереве (без изменений): `node ai/kit/step-budget-gate.ts` → `✓ every lazy directive under ai/directives/sdd-v2/** is within budget.`, exit 0 — зелено ровно потому, что монолиты не измеряются вовсе.

**Единственный технически честный способ** реализовать «бюджеты покрывают все директивы; монолит выше лимита роняет гейт» — перестать пропускать директивы без `steps/` и мерить их `skeletonText` тем же `check()` (уже агностичен к lazy/monolith — просто добавить их в скан с `packages: []`). Это ровно то, что говорит акцептанс. Но при текущем состоянии дерева это **немедленно** делает `infra.directive.xml` (9633 > 8000) находкой уровня `error`, `check:directive-budgets` возвращает exit 1, и обязательная финальная проверка пачки `npm run audit:sdd-templates` (которая вызывает `check:directive-budgets` последним шагом) становится красной — не гипотетически, проверено:

```
$ node ai/kit/step-budget-gate.ts   # СЕЙЧАС, без изменений
✓ every lazy directive under ai/directives/sdd-v2/** is within budget.
$ echo $?
0
```
— и с гипотетическим включением монолитов в скан (проверено локально на копии функции, не закоммичено) `infra.directive.xml` даёт `✗ infra (skeleton): skeleton tokens (hard limit) = 9633 exceeds 8000 by 1633 — build fails`, exit 1.

## Почему это не решается в рамках Зоны этой пачки

- Лечение (`lazy-split` для `infra`/`root`/`migration-v1-v2`/`router`) требует править `ai/kit/templates/sdd-v2/{infra,root,migration-v1-v2,router}.directive.hbs` — эти файлы **не входят** в Зону Пачки 19 («Зона: `ai/kit/templates/sdd-v2/{scope,module}.directive.hbs`, `ai/kit/assembly-manifest.json`, `ai/kit/step-budget-gate.ts`, аксиомы масштаба/pivot/стиля, тесты kit»).
- Единственная альтернатива — молча завести baseline/allowlist-исключение для уже-нарушающих монолитов (по образцу `GAP-B-1`/`gate:sdd-check-baseline`, но для этого гейта отдельно не заведено операторским решением) — прямо запрещена правилом стоп-класса 2 из `70-ORCHESTRATION-PROTOCOL.md`: «красная задача не чинится втихую расширением baseline (изменение baseline — отдельное operator-approved решение)».
- Нарушить инвариант «бюджеты покрывают все директивы» частично (например, включить скан только для новых/гипотетических монолитов, а существующие молча исключить без operator-approved механизма) означало бы придумывать архитектуру экземпляра гейта самостоятельно, не предусмотренную брифом буквально — тоже не мой выбор как исполнителя.
