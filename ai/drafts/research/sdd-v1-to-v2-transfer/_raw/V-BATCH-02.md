## C. REL-2 / `.npmignore` — причина, рабочий фикс, статус блокера

**Числа отчёта воспроизведены точно** (`npm pack --dry-run --json --pack-destination <scratch> <rc-w2>`, npm **10.9.3**):
```
name gennady  version 2.0.0-draft.1  entryCount 3217  unpackedSize 12698537 (12.11 MiB)
offenders (сегмент __tests__/__mocks__/__snapshots__/fixtures либо файл *.test.*/*.spec.*/*.snap): 70  (529 710 байт)
    ai/flow-eval/__tests__/harness.test.ts, ai/flow-eval/__tests__/fixtures/p9-misunderstood-cases.json, …
```
ПОДТВЕРЖДЕНО: 3217 / 12 698 537 / 70 — совпадают с отчётом до последней цифры. Раскладка: 35 «грязных» путей в `ai/**` и 35 их копий в `dist/ai/**` (`prepare-publish-artifacts.ts` копирует весь `ai` → `dist/ai`, `cpSync recursive`, поэтому весь мусор дублируется; `ai/` 3,66 МБ и `dist/ai/` 3,66 МБ — основной вклад в 12 МБ даёт это дублирование, а не тесты: тесты — 0,5 МБ из 12,1).

**Проверка причины (изолированный эксперимент, npm 10.9.3, 5 кейсов):**

| Кейс | Результат |
|---|---|
| `files:["a/**/*"]` + **корневой** `.npmignore` (`skip.txt`, `*.test.ts`, `__tests__/`) | все файлы, включая тесты, **в пакете** → корневой `.npmignore` инертен |
| `files:["a/**/*"]` + **вложенный** `a/.npmignore` | тесты и `skip.txt` **исключены**, сам `.npmignore` в тарбол не попадает |
| `files:["a/**/*","!a/**/*.test.ts","!a/__tests__/**"]` | тесты **исключены** → `files[]` поддерживает `!`-отрицания |
| `files:["a/**/*","!a/skip.txt"]` | `skip.txt` исключён |
| корневой + вложенный вместе | вложенный побеждает |

ПОДТВЕРЖДЕНО (причина названа исполнителем верно), но **ОПРОВЕРГНУТО в формулировке**: утверждение «`.npmignore` не применяется вообще, независимо от синтаксиса паттерна» слишком сильное. Документированное поведение npm: корневой `.npmignore` не переопределяет `files`, **вложенные — переопределяют**. Из-за слишком сильной формулировки отчёт закрывает дверь к дешёвому фиксу и предлагает оператору ложную дилемму («сузить `files[]`» = пересечение с REL-5 либо «`.npmignore` — дохлый механизм»).

**Рабочий фикс (проверен мной, размер S, вне зоны REL-5):** добавить **один** файл `ai/.npmignore` с вычитающими паттернами (`__tests__/`, `__mocks__/`, `__snapshots__/`, `*.test.*`, `*.spec.*`, `*.snap`, `fixtures/`, `.baseline/`). Он (1) вычитает мусор из `ai/**` в тарболе и (2) автоматически попадает в `dist/ai/.npmignore` при `cpSync(ai → dist/ai)` в `prepare-publish-artifacts.ts` (дотфайлы копируются — в `dist/ai` уже лежат `.baseline/` и `.gennady-directive-assembly.json`), т.е. вычитает и зеркало в `dist`. Проверено отдельным репро с `files:["dist/**/*","ai/**/*"]` и `.npmignore` на обеих глубинах: остаются только рантайм-файлы, сами `.npmignore` не пакуются. `package.json`/`files[]` при этом не трогается → нулевое пересечение с REL-5. Альтернатива — `!`-отрицания прямо в `files[]` (тоже работает), но это правка `files[]`, т.е. территория REL-5.
**Блокер ли?** Для **открытия PR** — нет (добавленный `.npmignore` идентичен main, безвреден, а при снятии `files[]` в будущем станет рабочим). Для **релиза** (A9/P1 «тарбол = allowlist МИНУС тесты/фикстуры») — да: пакет уезжает потребителю с 70 тестовыми/фикстурными путями. Фикс S и уже спроектирован → отдельная задача REL-2a до релиза (или добавить 7-м коммитом в этот же PR — решение оператора).
**Правка в план:** `34-TRACK-RELEASE-PACKAGE.md:351` содержит ложную посылку «`.npmignore` работает поверх любого `files[]`» — из неё и вырос неисполнимый критерий приёмки REL-2. Строку `:351` и формулировку инварианта **P1** (`:336`) надо исправить: вычитание работает только вложенными `.npmignore` (или `!` в `files[]`).

**ОПРОВЕРГНУТО (факт в сводном отчёте):** «`.baseline`-файлов (`ai/flow-eval/.baseline/**`) в пакете НЕ обнаружено». Фактически в тарболе **8** таких путей: `ai/flow-eval/.baseline/{README.md,before-report.md,environment.json,sdd-check-227c03a8.json}` и те же четыре под `dist/ai/flow-eval/.baseline/`.
