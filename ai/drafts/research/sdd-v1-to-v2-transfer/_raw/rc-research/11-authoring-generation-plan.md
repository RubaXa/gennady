# P8: Генерация спеки целиком + структурный адаптивный чекер с авто-фиксом

Контекст: P7.1 показал — worker заполняет спеку ТОЧЕЧНО (edit 1492 / patch 537 / write 99, 20–36 tool-вызовов
на прогон), выверяя уровни заголовков (`####`) под контракт-формат, и не укладывается в бюджет.
Спеки создаются (218 + 192 строки), но не добиваются, и остаются непочищенные `<!--` подсказки скелета.
Корень: `sdd-new` создаёт файл-скелет → модель редактирует его посекционно (edit-режим) + придирчивый
формат заставляет выверять байты. Решение — генерация документа целиком + структурный чекер.

## Принципы (согласованы оператором)

1. **Authoring = генерация документа целиком, не точечная правка.**
   - `sdd-new` по-прежнему создаёт файл-скелет на диске (скелет = источник структуры, формата и инструкций).
   - worker читает скелет → генерирует ВЕСЬ документ → записывает ОДНИМ `Write` поверх скелета.
   - Точечные edit по секциям в authoring запрещены. Комментарии-подсказки скелета (`<!-- ... -->`)
     заменяются контентом при генерации (в готовой спеке их не остаётся).

2. **Скелет — правильный эталон структуры.**
   - Секции с чётко определёнными уровнями заголовков (стандартный документ).
   - Скелет должен быть корректным сам по себе — это источник, по которому проверяется результат.

3. **Чекер `sdd-check --spec --authoring` — структурный, адаптивный, НЕ побайтовый.**
   Проверяет:
   - все ли секции на месте и на правильных уровнях заголовков;
   - маркеры расставлены правильно;
   - где должен быть список — список; где требования — формат требований (с ID); и т.д.
   Не придирается к байтам (пробелы, тривиальные отступы).

4. **Чекер сам фиксит мелочи (auto-fix).**
   - Лишние пробелы, тривиальные отступы, мелкие отклонения формата — чекер ИСПРАВЛЯЕТ, а не бьёт.
   - Содержательные пробелы (незаполненная секция, нет негативных сценариев, нет REQ-ID) — подсказка, не блок.

5. **Корпус фикстур разных документов.**
   - Набор spec-документов: корректные + с типичными «корёжениями» модели (не тот уровень заголовка,
     лишние пробелы, список прозой вместо списка, требования без ID, остаточные `<!--` подсказки).
   - Тесты: чекер (а) правильно валидирует структуру, (б) правильно авто-фиксит мелочи,
     (в) НЕ даёт false-positive на легитимных вариациях.
   - Реальные данные для фикстур брать из прошлых прогонов (напр. незаполненные/непочищенные
     `fibonacci.spec.md` и `nth.spec.md` из песочниц) — это документированные примеры того, что модель корёжит.

6. **Адаптивная калибровка по прогонам.**
   - Собирать, куда модель реально «корёжит» (из worker-сессий каждого прогона), и подстраивать
     допуски чекера / уровни скелета под реальное поведение — чтобы не было false срабатываний.
   - Допуски не выдумывать — выводить из фактов прогонов.

7. **Бюджет — вторично.** Сначала генерация-целиком + структурный чекер; замерить, укладывается ли worker.
   Только если после этого не хватает времени — поднять observation-бюджет с записью в журнал отклонений.

## Порядок (пакеты, каждый = отдельный коммит с зелёным pre-commit)

- **P8.1 Корпус фикстур + тесты чекера (сначала, до правок flow).** Собрать документы (корректные +
  корёженые из реальных прогонов), написать тесты валидации и авто-фикса. Часть обязана падать на
  текущем чекере (фиксируем это), часть закрепляет ожидаемое поведение.
- **P8.2 Структурный чекер + auto-fix.** Довести `sdd-check --spec --authoring` до структурной адаптивной
  проверки (заголовки, секции, маркеры, списки, требования) с авто-фиксом мелочей. Зелёные P8.1 тесты.
- **P8.3 Генерация целиком.** flow/директива: «прочитай скелет → сгенерируй весь документ → один Write
  поверх; точечные edit запрещены; подсказки скелета заменяются контентом». Проверить, что скелет-секции
  по уровням корректны.
- **P8.4 Верификация.** Один P7.1 прогон (тот же анти-цикл §8). Замерить: число tool-вызовов упало?
  worker уложился? Собрать, куда корёжит → в корпус фикстур (обратная связь для P8.6-калибровки).

## Анти-цикл (наследуется)
Один живой прогон на пакет; fail/inconclusive = стоп + отчёт; правки чекера/фикстур и правки flow —
разными коммитами; калибровка допусков — только из фактов прогонов, не из догадок.
