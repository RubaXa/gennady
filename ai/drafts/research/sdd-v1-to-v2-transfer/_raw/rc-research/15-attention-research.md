# H-attention: ресёрч — напоминание фазы против потери фокуса в длинном flow

Гипотеза оператора: при перетекании фаз (authoring→scaffold→execute) модель теряет, в какой фазе она и какой
инструкции следует; нужно точечно напоминать фазу (переякоривание внимания, не пересказ).

## Вердикт: подтверждается ПО ЭФФЕКТУ, но механизм уточнён

- **Не** sparse/sliding-window attention (у топ-API-моделей её в этом смысле нет).
- **Да** — позиционный bias **«lost in the middle»** (U-образный: начало и конец читаются, середина проваливается),
  **context rot** (следование инструкциям деградирует с ростом контекста, заметно уже с ~3000 токенов; на 80K+ адгезия
  к system-prompt падает), конечный **attention budget**.
- Наблюдение chain-2b (worker на scaffold полез в authoring-директиву) — это притяжение к раньше/ярче объявленной
  инструкции + недоразличение конкурирующих директив, а не «выпало за окно».
- Диагноз важен для лекарства: против «выпало за окно» — retrieval; против «внимание ушло не на ту инструкцию» —
  переякоривание/эмфаза на recency. Наш случай — второе.

## Что работает (методики напоминания)

| Приём | Подтверждение | Оговорка |
|---|---|---|
| **Recency-позиция** активной инструкции (в конце, у точки действия) | Anthropic long-context (+до 30%); primacy/recency | конец эксплуатируем, не императивничать |
| **Короткий structured «current phase» якорь** (1–3 строки) | Claude Code system-reminders; task-state | не пересказ директивы |
| **Recitation** (worker сам проговаривает фазу/цель перед шагом) | RECITE; Anthropic note-taking | стоит токенов и одного «хода» |
| **Re-inject у точки решения, не «всегда»** | Proactive Memory Agent; Claude Code | условно, иначе bloat |
| Markup-эмфаза («**ВАЖНО**», звёздочки) | слабо | без attention-steering ненадёжно |
| Прямой attention steering (PASTA) | сильно (+22%) | недоступно для API-модели |

**Рекомендуемая форма** (не пересказ, а компактный state-header максимальной recency перед решением worker'а):
```
<current-phase>scaffold</current-phase>
<active-rule>Читай ТОЛЬКО директивы фазы scaffold; authoring-директивы в этой фазе игнорируй.</active-rule>
```
+ опц. one-line recitation от worker'а первым токеном ответа («Я в фазе scaffold, следую scaffold-rules»).

## Контраргументы (дозировка важнее факта)

- Prompt bloat: напоминание = токены, добавляют к context rot; деградация reasoning уже с ~3000 токенов.
- Over-reminding реален: в Claude Code скрытые system-reminders «съедали 15%+ окна» (#17601) — вредит при переборе.
- Слабый сигнал (markup без steering) часто игнорируется.
- Recency-впрыск эксплуатируем/конфликтен: императивное напоминание в конце может перебивать легитимное рассуждение.
- Вывод: **одно короткое напоминание у точки действия — хорошо; периодический спам всей директивой — хуже.**

## Дизайн A/B (eval-харнесс, дешёвая модель, многофазный flow)

Условия (одинаковые задачи/сиды, варьировать только якорь):
- **A (контроль):** фаза объявлена один раз в начале, дальше не напоминается (текущее).
- **B:** перед каждым ходом worker'а в КОНЕЦ контекста — короткий `<current-phase>`+`<active-rule>` (2–4 строки, только текущая фаза, явный запрет чужих директив).
- **B2:** B + worker начинает ответ с one-line recitation фазы (recite-then-act).
- **A′ (ПЛАЦЕБО):** впрыск нейтрального текста той же длины, что B — отделить эффект содержания от эффекта длины.

Метрики: **phase_leak** (главная — обращения к директивам/файлам не своей фазы), tool_calls, budget_fit, pass,
input-токены (цена якоря), длина до первого phase_leak.

Подтверждение: значимое снижение phase_leak в B/B2 против A **и против плацебо A′**, при pass не ниже и budget не хуже.
Опровержение/оговорка: B≈A′ (работает длина, не содержание) ИЛИ B снижает leak, но роняет pass/рвёт бюджет (over-reminding) → урезать якорь.

## Связь с нашим flow
Claude Code сам применяет этот приём (system-reminders на recency). Наш SDD flow объявляет фазу один раз в директиве
(начало) → к моменту действия она в «середине» → lost-in-the-middle. Лекарство: `sdd-state`/`sdd-task` выводы уже дают
must-remember блок (P9 WORKING_DIR) — добавить туда `<current-phase>`+`<active-rule>` на recency. Применять после базовой линии.

engineering, RECITE (2210.01296), PASTA (2311.02262), StreamingLLM (2309.17453), Claude Code internals, Prompt Bloat (claude-code #17601).
