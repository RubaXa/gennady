## ЦЕНТРАЛЬНЫЙ ВЫВОД (стержень всей работы)
**Flow пережат: он ДИКТУЕТ агенту жёсткую траекторию вместо того, чтобы ПОМОГАТЬ ему по состоянию артефактов.**
Это исходный тезис оператора (сессия 1: «перегнули с директивами/инструментами, загнали в невыполнимые рамки»),
теперь доказанный на конкретике: chain-2 — жёсткая next-подсказка `AUTHORING_SCOPE_NEXT` сломала траекторию
(«сначала approve в portal»), агент застрял не по неспособности, а потому что flow запретил продолжить с готовыми спеками.
Фазы по отдельности работают (2/2×3) — там траектория не упирается в жёсткую границу; ломается именно ПЕРЕХОД.

**Направление фикса:** flow ПОМОГАЕТ (детерминированно проверяет артефакты, мягко намекает «спеки готовы → обычно scaffold»),
а НЕ диктует («СНАЧАЛА сделай Y, иначе стоп»). Подтверждено ресёрчами: soft hints > hard gates; enforcement — на уровне
детерминированной проверки состояния инструментом, не жёсткого промпт/next-императива.
**Баланс-оговорка (честно):** «дать волю» ≠ убрать всё — ранние провалы были, когда агент разбредался (уходил в чужой tmp,
изобретал маршруты). Цель: мягкая помощь + детерминированная проверка артефактов, не диктовка траектории и не анархия.



Сжатый обучающий слой (для памяти проекта и спецификации). Append-only, плотно.
Роли документов: **PROGRESS.md** = текущее состояние (recovery). **13-genetic-loop.md** = метод + полный журнал прогонов.
**Этот файл** = выводы: гипотезы → результат → эффект → решение. Каждая строка — один урок.

## КОРНЕВОЙ ПАТТЕРН (chain5): worker оставляет плейсхолдеры скелета, валидаторы дают запутанные вторичные ошибки
Прогоны chain2–5 вскрыли ОДИН корень: worker недетерминированно НЕ дозаполняет плейсхолдеры скелета `<...>`
(bootstrap-строка, `<module>` в Module Map, ...). Разные валидаторы ловят это ПО-РАЗНОМУ и ЗАПУТАННО:
- bootstrap: «row has no Kind» / «schema found 0 tables»
- module-map: decomposition-парсер читает `<module>` как ИМЯ модуля → «declared module <module> missing» (вместо «заполни плейсхолдер»)
Точечные фиксы каждого валидатора = marathon (5 прогонов, каждый новый плейсхолдер). chain5: bootstrap ПОБЕЖДЁН
(spec-schema=current), но всплыл `<module>`. Победы реальны, но по одному — бесконечно.
СМЕНА ТАКТИКИ: (1) единый placeholder-gate — ОДНА ясная ошибка про ВСЕ незаполненные `<...>` ПЕРВОЙ, до вторичных;
(2) flow направляет worker вызвать sdd-check --spec ПЕРЕД Approval #1 (self-check в цикле) → worker дозаполняет детерминированнее.
Плюс: authoring сам недетерминирован (chain3/4 pass, chain5 fail) — self-check стабилизирует.
