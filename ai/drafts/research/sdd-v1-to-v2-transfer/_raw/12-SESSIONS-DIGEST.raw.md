## 4. Дизайн универсального verify

### 4.1 Тезис (DL-3, `01` §A.7–A.8)
PR#5 и v2 «решают одну задачу разными половинами»: v2 — глубина/честность на одном стеке (лестница `type-check → test/test:coverage → format:fix → lint:fix → lint → format → yagni`, профили `setup/code/test/full`, readiness «7 кирпичей + 2 обёртки», детекторы честности `isStubScript`/`isVacuousScript`/`verifyCoverageWritten`/`testcov --min`, один вызов на фазу, repair-pass D-SV014), но хардкод `npm run <script>` (`sdd-verify.cmd.ts:240-243`, тогда). PR#5 — широта (детект стека, «гейт как данные», `ENV_FAIL`/`timeout`/`violation`, clean-tree guard D-STACK-017, `gennady.yaml`), но без честности, фаз, готовности, и с v1-эровой bash-делегацией `verify.sh`. Решение — **срастить**: ядро семантики v2 + примитивы PR#5. Выкинуто: хардкод `npm run` (v2); `verify.sh`/`classify-scripts` (PR#5, v2 удалил bash `bd33d113`); полная плагин-папочная машинерия и golang-плагин — **отложены** (O-1/O-5).

### 4.2 Итоговая архитектура — Engine ↔ Preset ↔ Detector (сообщение 27.08 14:45, ответ на Р-42)
- **Detector**: `package.json` → пресет `nodejs` (дефолт); `go.mod` → `golang`; `gennady.yaml`/`.gennadyrc` → «custom config обнаружен, поддержка отложена», используется авто-пресет.
- **Engine** (стеко-агностичен, владеет инвариантами v2): порядок лестницы (cheapest-most-important-first), halt на фундаменте, repair-pass (tree-fingerprint), профили; рендер вердикта + маркеры `✅/🔧/⏭/⛔` + новые `env-fail/timeout/violation`; **концепт честности** (required `missing`/`vacuous` → красный; coverage без свежего отчёта → красный); clean-tree guard + checkpoint + enforcement `mutationPolicy`; classify spawn-ENOENT/timeout.
- **Preset** — исполняемый модуль. Контракт (эскиз ассистента, дословно):
```ts
interface StackPreset {
  id: 'nodejs' | 'golang' | string;
  detect(root): boolean;                          // авто-детект окружения
  resolveGates(profile, root): ResolvedGate[];    // лестница как ДАННЫЕ: роль→argv, present/missing/vacuous решает пресет
  coverageProbe?(root): CoverageProbe;            // per-stack свежесть покрытия (node: coverage-final.json; go: coverage.out)
  readiness?(root): ReadinessBricks;              // per-stack «обязанности», для sdd-state/sdd-task
}
type ResolvedGate = {
  role: 'type-check'|'test'|'test:coverage'|'format:fix'|'lint:fix'|'lint'|'format'|'yagni'|string; // + кастом
  argv?: string[]; cmd?: string;                  // как исполнять (XOR)
  status?: 'runnable'|'missing'|'vacuous'|'skipped'; // вердикт пресета о доступности
  mutates: boolean; haltsOnFailure: boolean; required: boolean;
  mutationPolicy?: 'forbid'|'keep-fix'|'drift-signal'; timeoutMs?: number;
};
```
- **Разрез честности**: концепт — в Engine, детекция — в Preset (node решает `status:'vacuous'` через `isVacuousScript`; Engine: `vacuous + required` → красный; «нет свежего отчёта → красный» — Engine, какой файл/как — `coverageProbe`).
- **Пресет `nodejs`** = parity с текущим: роли = `GATES`; `resolveNpmScriptName` (alias `typecheck`→`type-check`), `readProjectScripts`, `isVacuousScript` → `argv=['npm','run',<script>]`/`status`; `yagni` → `via gennady` (стеко-агностичный, одинаков в обоих пресетах); `coverageProbe` = clear/wroteFresh `coverage/coverage-final.json`; `mutationPolicy`: `format:fix`/`lint:fix`=`keep-fix`, остальные `forbid`.
- **Пресет `golang`** (валидирует, что интерфейс не «node-образный»): `type-check`→`go build ./...` (halts); `test`→`go test ./...`; `test:coverage`→`go test -coverprofile=coverage.out ./...`, `coverageProbe`=свежесть `coverage.out`; `format:fix`→`gofmt -w .` (keep-fix); `format`→`gofmt -l .` (непустой вывод = fail); `lint`→`golangci-lint run` (нет бинаря → `env-fail`, не fail); `go generate`=`drift-signal`; `build`=`forbid`.
